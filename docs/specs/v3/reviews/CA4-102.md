# CA4-102 — forward correction while the cycle floor holds

**Status:** specification reviewed (2026-10-15).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Approved decisions.** CA4-20: threshold strictly greater than 1 s; cycle instant
  `max(wall, previous + 1 µs)`; every discontinuity opens a process-wide `clock_discontinuity`
  gap. CA4-98: backward corrections ahead of the floor take forward-jump bounds; periodic-check
  detection acts at detection and bounds the gap on adjacent cycle instants.
- **Gap.** §3.5 did not cover a forward correction while an earlier backward correction still
  holds the floor. The periodic-check clause "or later under the frozen-floor rule above" allowed
  the end rule to depend on the detection point. Implementation counterexample: floor 100,
  bootstrap wall 90 (cycle 100.000001), then wall 94 at monotonic 1 (+3 s). Cycle-start detection
  ended the new gap at 100.000002; periodic detection kept it open until floor recovery.
- **Reused construct.** The existing forward-jump bounds and frozen-floor bounds, now selected
  per correction. No new type, field or diagnostic kind.
- **Owner/dependents.** Layer 0 §3.5 (owner), §4.4, §10, §13.

## Decision

1. Each discontinuity opens its own gap. Its bounds depend only on its own correction: direction
   and, for a backward correction, whether it leaves the wall clock behind the floor.
2. The detection point (cycle start or periodic check) never changes the end rule.
3. A forward correction while the floor holds ends at the first cycle instant after detection,
   even if that instant is frozen. The earlier backward gap stays open independently until a
   cycle's wall reading exceeds the floor.
4. A further backward correction over 1 s while the floor holds takes frozen-floor bounds from
   its own first frozen cycle instant.
5. Diagnostics report each gap with its boundaries and end rule.

**Rejected alternative.** Making the forward gap wait for floor recovery. The frozen interval is
already covered by the earlier gap; the wait only widens the forward gap and makes its end depend
on an unrelated correction.

Unchanged: >1 s threshold, `wall_clock` due/basis and re-arm, elapsed monotonic waits,
bootstrap/downtime separation, §4.4 durable acknowledgement before a read past a boundary is
complete.

## Scenario review

| Scenario | Result |
|---|---|
| Floor 100, wall 90 → 94 (+3 s over 1 s), detected at cycle start | New gap 100.000001 → 100.000002, ended; bootstrap gap open. |
| Same, detected by the periodic check; next cycle wall 95 | New gap 100.000001 → 100.000002 at that cycle, no floor wait; bootstrap gap open. |
| Later cycle wall 100.5 | Bootstrap gap ends at that cycle; forward gap unaffected. |
| Forward correction that lifts the wall above the floor | Forward gap ends at the first cycle after detection; the backward gap ends at the same cycle (wall exceeds floor). Two gaps, two records. |
| Further −5 s correction while frozen | Own frozen-floor gap from its first frozen instant until wall exceeds floor. |
| −0.5 s while frozen | No new gap; `clock_regression` only (wall behind floor). |
| Read spanning a gap whose end is unacknowledged | Incomplete (§4.4). |
| Armed `elapsed` hold during both corrections | Expires on monotonic time. |

Textual review only; no V3 runtime test has run. Codex implements the per-correction end rule in
`CycleClock.compare` / `ClockGap.finish`.
