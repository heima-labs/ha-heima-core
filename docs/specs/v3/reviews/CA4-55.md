# CA4-55 — checkpoint failure classification review

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

The existing Layer 0 §7.3 rule keeps a failed checkpoint dirty for retry and emits a
persistence diagnostic. Layer 0 §7.1 defines `degraded_recovery` by unavailable current
entities. Section 8 previously reused that classification for a write failure. The
correction aligns §8 with §7.3, adds separate diagnostic visibility in §10, and adds an
acceptance case. It changes no recovery baseline or actuator policy in §7.4.

| ID | Current inputs and checkpoint | Required result |
|---|---|---|
| S1 | Inputs normal; checkpoint replacement fails | `RecoveryState` remains `normal`; dirty retry and persistence diagnostic are visible |
| S2 | Many entities unavailable; checkpoint write succeeds | §7.1 classifies `degraded_recovery` from current inputs |
| S3 | Prior projection missing or unusable after a failure | No historical baseline for that entity; absence is not evidence of unchanged state |

**Review result:** §7.1, §7.3, §8, §10 and the Layer 0 acceptance text agree on these
three cases. No executable V3 test has run.
