# CA4-04 — historical boundary coverage review

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decision and impact

The developer chose to report incomplete history when the predecessor needed
for a state-window reconstruction is gone. The existing `retention_coverage` and
Layer-5 abstention mechanisms carry that result; no extra retained predecessor
or history store is added. Layer 0 §4.0–4.3 owns reconstruction, retention and
the in-memory view. Layer 3 §4.2 already refuses truncated required history;
Layer 5 §5.1 now distinguishes an incomplete view from a complete empty event
interval. This applies to every state stream, including lights, valves and
temperatures, and to event streams without manufacturing a predecessor.

| ID | Scenario | Required result |
|---|---|---|
| S1 | A at day 0, B at day 20; A pruned; query days 10–21 | Truncated: state at day 10 is unknown |
| S2 | Stable A remains the protected latest record beyond retention | A is a valid predecessor; time retention alone does not truncate an in-window query |
| S3 | Intermediate B pruned but older A survives | Early-pruning marker prevents A from falsely certifying the initial state |
| S4 | Short-term window begins before process observation or lacks its state predecessor | Frozen read is `None`; Layer 5 abstains |
| S5 | Complete event window with no event | Frozen read is an empty tuple, a valid zero-event result |
| S6 | Count pruning affects one Location but not another | Coverage is stream-scoped; only dependent reads are truncated |

**Review result:** the new owner text and existing Layer-3 complete-history gate
agree on these scenarios. The single early-pruning marker may conservatively
report `truncated` for an unaffected state window; it never reports a missing
transition as complete. Executable retention and frozen-view tests remain for
the V3 implementation phase.
