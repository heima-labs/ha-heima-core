# CA4-74 — descriptor-based families for Reaction notices; Layer-6 review residues

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision

`ReactionFollowUpIntent`, `ReactionFollowUpOccurrence` and `ReactionActionNoticeOccurrence` carry
`reaction_descriptor_id`. Layer 6 maps the descriptor namespace to the notification family with
one closed core table, for follow-up, availability and action notices.

## Overlap check

The descriptor id is an existing identity of the configured Reaction; the family decision stays in
Layer 6. The follow-up fact context gains one scalar key, still within the depth-two/8 KiB bounds
(recomputed examples: 891, 786, 856 bytes).

## Residues corrected

| Place | Correction |
|---|---|
| Layer 1 §3.1 and acceptance | No dedup/rate-limiting window; key is delivery identity. |
| Layer 3 §6.3.1 | Delivery behavior is fixed by Layer 6, not configurable channel/grouping. |
| Layer 5 §6.0 | A delivered advice is cleared silently, never retracted with a message. |
| Overview, recap | Wording aligned with item-tag replacement and family quiet hours. |

## Scenario review

| Scenario | Result |
|---|---|
| Weather-protection step unconfirmed at 03:00 in quiet hours | `safety` follow-up, delivered at once. |
| Solar-shading step unconfirmed at 03:00 | `attention`, held until quiet hours end. |
| Binding for a descriptor namespace absent from the table | Rejected at staging. |
| Recovery of a prepared follow-up intent | Descriptor id comes from the intent; identities still must match. |

Textual review only; no V3 runtime test has run.
