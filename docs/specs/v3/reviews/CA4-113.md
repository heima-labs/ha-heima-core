# CA4-113 — map card and map access for users without a role

**Status:** specification reviewed (2026-10-16).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 8 §4 roles and §15.1 (no role: "not set up" page); §5.2 panel
  states; §9 map, §9.8 control through HA as the signed-in user, §9.12 list view, §9.13 pan and
  zoom; §13 Lit frontend and message catalog.
- **Gap.** No map outside the panel; a wall tablet's dedicated HA user or a guest account, holding
  neither role, could not see the map.
- **Overlap check.** No new role: the map is opened to every HA user instead. The card is the same
  component as the Overview map, not a second map. Layout revisions extend `subscribe`, not a new
  message. Card options are Lovelace card configuration, not Heima configuration or layout data.
- **Owner.** Layer 8 §4, §5.2, §9.10, §9.11, §9.14, §13, §15, §16.

## Decisions (developer-approved)

1. The house map is visible to every authenticated HA user; a user with no role sees the Overview
   with the map only, in resident wording. Every other section and command keeps its roles.
2. `custom:heima-map-card`, registered by the integration, same component; map only, no editor.
3. Card options `floor`, `controls`, `control_rooms`, `idle_reset`.
4. `control_rooms` limits what the card offers; it is not a security boundary, since HA has no
   per-entity permissions. A per-HA-user scope editable by residents is deferred.
5. The card resynchronizes on reconnection, shows §5.2 states compactly and redraws on a new
   layout revision pushed by `subscribe`.
6. Guests are to be discussed in depth after the Layer 8 completeness review (backlog, open
   question 5).

## Scenario review

| Scenario | Result |
|---|---|
| Wall tablet with a dedicated non-admin HA user | Card shows the map; `overview` and `subscribe` accept it for the map part. |
| Guest-room tablet locked to one dashboard, `control_rooms: [guest_room]` | Guest toggles the guest-room light; the living room is visible but inert. |
| Guest with an HA account opens the Heima panel | Overview with the map only; no other section or command. |
| Same guest uses an HA dashboard to switch the living-room light | Possible: HA permissions, outside Heima; the card scope does not claim otherwise. |
| Administrator saves a new layout | Open cards and panels redraw from the new revision. |
| HA restarts while the tablet is on | Compact "not reachable" line, then resynchronization. |

Textual review only; no V3 runtime test has run.
