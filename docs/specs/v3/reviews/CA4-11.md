# CA4-11 — profile-free direct Reaction plan

**Status:** specification reviewed (2026-10-07).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved direction and exact gap

CA2-1 permits an `admin_direct` Reaction with `relation_profile=None` and one
descriptor-level `ReactionGuardContractRef`. The developer confirmed that the
versioned descriptor supplies the direct plan grammar; a learned relation
profile may narrow it for `learner_proposal`. Both paths retain the same
`ReactionEvaluationPlan`, `CanonicalEnvelope`, evaluator, scheduler, admission,
and `ApplyStep` protocol. A direct envelope retains the same axes/cell lookup,
but cannot claim invented learner support or calibration. Presence simulation
has zero axes and one admitted empty-key cell. A step-programmed descriptor
uses its existing versioned activation start criteria and next-step slot;
departure, calendar changes and jobs request re-evaluation and are not new
temporal primitives.

The owner text still makes the relation-profile policy facet the sole source
of runtime slots/comparisons in Layer 5 §5.1 and of permitted envelope axes in
Layer 3 §6.5. `CoverageCell` requires learner evidence even for a direct-only
descriptor. The five temporal primitives in Layer 5 §5.1 are presented as the
only form for every plan, without distinguishing programmed activation entry.

## Reused constructs, owners, constraints

Layer 5 §3.2 already owns the bootstrap-frozen descriptor validators/compiler
and direct guard contract; §3.2 also owns activation start/end identity. §4.2
owns immutable plan/configuration identity, §5.1 the shared evaluation grammar,
§6.0 the activation-stable `AtJob` slot, and §7.2 the presence-simulation
fixtures. Layer 3 §6.5 owns `CanonicalEnvelope` axes, versioned partitions,
cell-key projection and exact lookup. Layer 4 §9.3 owns real departure/return
episodes and never fabricates a departure after restart. Overview, recap,
acceptance criteria, registry and backlog depend on these contracts.

V2-to-V3 constraints: one generic action path; no invented relation profile,
learner evidence, raw HA predicate, second scheduler, replayed departure,
device-specific evaluator or automatic authority from an envelope cell.

## Scenario matrix for semantic review

| Scenario | Required result |
|---|---|
| Direct presence simulation stages with `relation_profile=None` | Descriptor plan grammar, exact direct guard contract and complete common plan validate without a learner profile. |
| Direct envelope has zero axes | One empty-key cell passes exact lookup, while calendar, presence and ordinary guards still gate action. |
| A later direct descriptor declares bounded typed axes | Only versioned descriptor-permitted slots, partitions and joint cells stage; missing or unpartitionable current input abstains. |
| Learner proposal carries a cell | Positive support and calibration remain required; direct cells cannot be passed off as learned evidence. |
| HA restarts during a planned absence | Fresh current `away` plus active plan may start a new activation without a fabricated departure; missed steps are skipped. |
| Calendar becomes active while already away | Fresh evaluation starts only one activation when start criteria first pass. |
| Departure, calendar refresh and due job coincide | They request evaluation of one current snapshot and one activation; a duplicate job cannot dispatch twice. |
| Current presence becomes unavailable | Work abstains; no new activation or false normal exit; a later valid reading re-evaluates under current criteria. |
| Return or authority revocation | Existing normal-exit or immediate revocation path ends work; no new trigger or execution lane. |

## Semantic review result

The Layer-5 descriptor registration now names finite permitted axes and,
when direct authoring exists, exact permitted joint cell keys. The existing
compiler and validators own typed slots, temporal-plan shape, comparison
rules and parameter bounds. A selected learned profile narrows them, and its
policy facet explicitly names its permitted axes; the direct path has no
relation profile and uses its descriptor plus exact guard contract. Staging
can therefore reject an undeclared slot/axis/partition/cell without a
second plan type. Each cell of the existing `CanonicalEnvelope` keeps its
axis/value lookup contract. Layer 3 §6.5 requires a positive measured
`support` and `calibrated=True` for learner cells, and exactly two absent
evidence fields for direct cells. The immutable Reaction origin selects
that validation; runtime exact-cell lookup is unchanged. Presence
simulation's zero-axis envelope has one empty-key cell, not a fabricated
statistical sample, and cannot authorize action without calendar, presence,
session, guard, authority and Actuator admission.

The existing Layer-5 §3.2 activation contract already permits a program to
start when its descriptor's staged criteria become true, including from
fresh current inputs after restart. The same `ReactionEvaluationPlan.trigger`
field identifies those versioned criteria; the five §5.1 temporal primitives
remain for nonprogrammed triggers. Layer-4 departure is a real observed
episode and is not synthesized at bootstrap. Departure, calendar changes
and due jobs request the same frozen-snapshot evaluation; one live activation
id and the §6.0 next-step slot prevent duplicate starts and commands. A
temporary input gap preserves the activation without command; a verified
return closes it under the existing normal-exit contract; authority loss
uses the existing immediate revocation path. Neither case requires a new
temporal primitive, evaluator, scheduler, or command path.
