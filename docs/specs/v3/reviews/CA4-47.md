# CA4-47 — referenced contracts and solar-geometry producer

**Status:** specification reviewed (2026-10-07).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved direction and exact gap

V3 uses one typed substrate, frozen core registries, staged bindings and a single
Reaction/Actuator path. Existing decisions reuse Layer-1 `Location`/`LocationKey`
instead of `LocationSet` (CA4-48), keep the solar-incidence formula in Layer 2
(CA4-36), and keep solar geometry distinct from irradiance and from the
removed CA4-13 solar timing forecast. CA4-47 must not revive any of those
superseded mechanisms.

The cited Layer 0/3/4/5 names have no authoritative shape or are obsolete
aliases. Their absent validators leave scope, freshness, boundedness,
serialization or authority ambiguous. Layer 3 requires casa-scoped
`external.solar_elevation` and `external.solar_azimuth`; Layer 2 defines their
consuming formula, but no staged owner produces those facts.

## Owners and dependency closure

Layer 1 §5 owns scope values. Layer 0 §4.1 owns frozen short-term history.
Layer 2 §§2/5.3 owns HA ingress, formula inputs, producer claims and the solar
producer. Layer 3 §§4.4/6 owns reference/result/diagnostic payloads. Layer 4
§§4/9 owns semantic claim parameters, availability and activity slots. Layer 5
§§3/5 owns effect and action-bundle contracts. Overview, recap, acceptance,
registry and backlog follow the owner corrections.

## Counterexamples to check

| Case | Required boundary |
|---|---|
| Two openings in one room have different orientations | One casa solar pair feeds two separately staged per-opening formula bindings; no opening identity is guessed from the room. |
| Sun is below the horizon while its azimuth matches an opening | The geometric direct-incidence proxy is zero; the unguarded cosine would have been falsely positive. |
| Solar source is absent, stale, future-dated or malformed | Its geometry fact is unavailable, the dependent formula abstains, and an older value is never substituted. |
| Sun attribute updates share one HA cycle | Both normalized facts derive from that same frozen state; a later update belongs to the next cycle. |
| HA observer location or opening orientation changes | The affected source/formula generation is restaged and dependent learning artifacts invalidate; unrelated sources continue. |
| Solar facts are claimed by a second producer | Claim or reserved read-path staging fails before either producer can run. |
| A light and a valve occur in one routine bundle | The common bundle contract remains channel/intent based and rejects duplicate channels, never light-only. |
| A thermal artifact supplies recovery-duration bounds and a routine artifact supplies whole-bundle conditional frequency | Each output is validated under its exact registered profile-output schema and descriptor/profile compatibility; neither is copied into a candidate member or accepted as another intent's effect. |
| A learned occupancy signal cites its own semantic result as physical reference | Only the same-room `occupancy.physical` `FactSlot` with physical provenance is eligible; the feedback loop is rejected. |
| A historical window crosses a process gap or missing start state | The frozen view reports incomplete, never a fabricated empty event or stable state. |
| An activity context slot is unavailable | It cannot become an anchor or an inferred negative activity. |
| A future context hypothesis has no registered uncertainty schema | It cannot be published even though the draft payload uses bounded existing types. |
| A solar-dependent Reaction is held or loses consent during recovery | Source availability supplies no command authority; common Layer-5 hold, consent and guard gates still apply. |

The references in CA4-47 were checked against authoritative Layer 0–5 text:
`ScopeKind`, `HistoryViewRequirement`, `TimeRange`, `ActuationBundle`, `ClaimParameterSchema`,
`SemanticAvailabilityContract` and `ActivityEvidenceSlot` now have owner
contracts. `PhysicalOccupancyReference` is replaced by the existing
`FactSlot` plus physical provenance. `LocationSet` had already been replaced
by `Location` in CA4-48. The unused future names `UncertaintySummary` and
`OperatingEnvelopeRef` are replaced by bounded existing payload/envelope
types with an explicit future-schema publication gate. The solar source uses
the normal Layer-2 Sensor/claim/unit path, not a new device-specific pipeline.
CA4-47 originally defined `TypedEffectSummary` and `EffectShape` because
earlier text referenced them. CA4-12 later retired those duplicate current
contracts in favor of the exact profile-output hand-off and defined the
routine output schema. The routine profile's exact catalog registration
remains open. The original naming gap remains part of this review's history,
not a current consumer requirement.

These are specification scenarios. No executable V3 test has run.
