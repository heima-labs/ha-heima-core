# CA4-80 — configuration-derived committed-state subscriptions

**Status:** specification reviewed (2026-10-13).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision

Layer 0 §4.8: a core component may derive its exact-key subscriptions from the active composed
generation; they are re-declared atomically at each generation swap boundary. Still core-only,
exact keys, no patterns, no changes at other times.

## Alternative rejected

A bootstrap pattern subscription (`room_occupancy@*`): contradicts §4.8's exact-key rule and would
deliver keys no published entity needs.

## Scenario review

| Scenario | Result |
|---|---|
| Room added by a commit | New key receives its value once after the first new cycle; its HA entity appears. |
| Room removed | Its key stops; its HA entity is removed. |
| Unrelated commit | Unchanged keys keep pending state; no extra delivery. |
| Plugin tries to subscribe | Rejected. |

Textual review only; no V3 runtime test has run.
