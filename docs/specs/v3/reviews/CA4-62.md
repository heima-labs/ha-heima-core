# CA4-62 — one physical topology model with zone roles

**Status:** specification reviewed (2026-10-11).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Gap and research

V3 Layer 1 restated `Opening`/`ResolvedConnection` but not the V2 `room_type` that drives the derived
`connection_type`. V2's `room_type` mixes physical enclosure (`indoor`, `outdoor`, `balcony`) with
function (`garage`, `basement`, `transit`, `external`), and its `connection_type` is a security
alarm-boundary classification: a door to `outside` is `separate` because it is an independent
access point, not because it is not exterior. In V2 only doors form connections; a window has no
other side, which left the 12a `weather_exposed` default unable to see a plain exterior window.

| Concept | IFC | gbXML / EnergyPlus | openHAB | V3 decision |
|---|---|---|---|---|
| Space enclosure | `IfcSpace` INTERNAL/EXTERNAL | conditioned/unconditioned zones | `Indoor`/`Outdoor` locations | `enclosure` interior/exterior on the room |
| Opening other side | space boundaries, internal/external | surface adjacency (1 or 2 spaces), window outside boundary condition | — | `other_side` on every opening |
| Device position | `IsExternal` | interior/exterior shade | — | `Actuator.is_external` (12a) |
| Purpose groupings | `IfcZone` | thermal zones | — | `Zone` + closed `ZoneRole` binding |
| Security perimeter | not physical | — | — | future `security_perimeter` zone role; no stored connection class |

## Decisions (approved)

(a) `enclosure` has two physical values; conditioned/unconditioned is not a room attribute.
(b) `other_side` on every opening, default `outside`; only doors are passable connections.
(c) A window toward an interior garage is neither exterior-facing nor weather-exposed.
(d) Zone roles `thermal_envelope` (default all interior rooms) and `security_perimeter` (reserved).
Earlier effects remain: exterior rooms are part of casa presence; indoor learning slots bind only
thermal-envelope rooms; presence simulation admits exterior-room lights only explicitly.

## Overlap check

`Zone` is reused unchanged; the role binding is the only new construct. `connection_type` and its
override are removed rather than kept beside the new queries. No functional room label is promoted
to a rule input.

## Scenario review

| Scenario | Result |
|---|---|
| Window in living room, default `other_side` | Faces exterior; awning without `is_external` is weather-exposed. |
| Door-window from living room to a registered terrace (`exterior`) | Faces exterior; terrace evidence counts for casa presence. |
| Window from kitchen to an interior garage | Not exterior-facing; not exchange with outside; no wind requirement. |
| Unheated interior garage outside the thermal envelope | Excluded by binding `thermal_envelope` to a Zone without it; its temperature cannot bind `room_temperature`. |
| No `thermal_envelope` binding | All interior rooms are in the envelope. |
| Terrace light in presence simulation | Only if the terrace room or that light is explicitly selected. |
| Future perimeter alarm | Declares a `security_perimeter` Zone; no topology change. |

Textual review only; no V3 runtime test has run.
