# CA4-86 — HA administrators can answer resident requests

**Status:** specification reviewed (2026-10-13).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved, S1 of the CA6 reread)

The ingress actor category describes the HA account (`ha_admin` when HA confirms an
administrator, `resident` otherwise), not household membership. The three Initial-V3 response
owners declare both categories and keep their own narrower rules. The operational source kind
follows the verified category: `resident_response` for `resident`, `admin_command` for `ha_admin`.

## Alternatives rejected

- Multi-category ingress mapping (an administrator is also `resident`): changes the meaning of
  `resident` in resident-control provenance (Layer 0 §5.1.1) and correction attribution.
- Ingress reading Layer-6 recipients or `HouseholdConsentAuthority`: Layer 0 would depend on
  Layer 5/6 data.
- A separate non-admin HA account per administrator: unusable in a single-administrator home.

## Overlap check

No new type, field or owner: `allowed_actor_categories`, `actor_category`, `actor_ref` and both
source kinds already exist. `HouseholdConsentAuthority` stays the only consent membership rule.

## Changes

| Place | Change |
|---|---|
| Layer 0 §5 / §5.1 | `admin_command` also covers an administrator's verified ingress response; response kind follows category. |
| Layer 0 §5.1.3 | Category from HA's admin flag; `actor_ref` is the HA user id; owners for household members declare both categories. |
| Layer 0 §7.4.1 / §13 | Recovery request declares both categories; acceptance distinguishes resulting kinds. |
| Layer 5 §6.0 | Consent and advisory-feedback requests declare both categories; consent still checks `HouseholdConsentAuthority`; `admin_command` steps may carry an admitted Reaction identity. |
| Layer 8 §13 | `requests/answer` open to admin and resident roles. |

## Scenario review

| Scenario | Result |
|---|---|
| Administrator in `HouseholdConsentAuthority` taps grant on a notification | Accepted; same authority transition as the panel command. |
| Administrator not in `HouseholdConsentAuthority` taps grant | Passes ingress, rejected by the owner; nothing changes. |
| Administrator approves a recovery confirmation | Recovery `ApplyStep` with `kind="admin_command"`, actor category `ha_admin`. |
| Non-admin resident approves a recovery confirmation | `kind="resident_response"`, unchanged. |
| Administrator gives advisory feedback | One `reaction.advisory_feedback` fact with `actor_category="ha_admin"`. |
| Administrator answers an expired or withdrawn request | Rejected at ingress. |
| Single-administrator home, `require_confirmation` Actuator after power recovery | Confirmation answerable; recovery possible. |

Textual review only; no V3 runtime test has run.
