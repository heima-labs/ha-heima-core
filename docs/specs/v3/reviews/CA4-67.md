# CA4-67 — recovery confirmation delivery

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved, B2)

A typed `RecoveryConfirmationOccurrence` with phases `opened`/`closed` goes from Layer 0 to
Layer 6; Layer 6 renders the reserved `recovery.confirmation_request` event fact through the
unified outbox; answers return through the CA4-65 response ingress.

## Overlap check

Reuses the §7.4.1 request lifecycle, the unified outbox, the response ingress and the Layer 5 §6.0
facet codec. Not an advisory (a policy suggestion) nor a follow-up (a decided action outcome).

## Scenario review

| Scenario | Result |
|---|---|
| Request opens | One `opened` notification with approve/dismiss. |
| Same proposal next cycle | No second notification. |
| Approved, dismissed, expired or invalidated | One `closed` occurrence; Layer 6 removes the button. |
| Delivery fails | Request unchanged; expires on its deadline. |
| Restart with an open request | Request invalidated; its `closed` occurrence is produced. |

Textual review only; no V3 runtime test has run.
