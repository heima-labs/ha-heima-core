# CA4-06 — fusion epistemic change impact analysis

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact

Layer 2 §5.2 currently compares only candidate and committed values. Layer 0
§4.0/§4.2 instead persists a state change when availability, confidence or
stable source identity changes. An unavailable fact has no comparable value.
The Layer-2 dwell should apply to a change of available physical value; a
same-value confidence or provenance update should commit without restarting
dwell. Returning from unavailable to available must use the candidate's
normal directional dwell, if any.

The existing `FactSource.configuration_fingerprint` identifies the configured
fusion, not which input was selected at runtime. Add a bounded stable
`route_fingerprint` to provenance and `FactSourceFingerprint`, computed by the
fusion from the exact contributing input routes. For precedence this is the
selected `FactRef` and source fingerprint; for other strategies it is the
canonical set of contributing votes. It excludes per-cycle correlation ids and
free-form evidence. This reuses the existing write-on-change comparison rather
than creating a separate audit stream.

| ID | Scenario | Required result |
|---|---|---|
| S1 | Available `True/.9` becomes `True/.2` | New fact in the same cycle; no value dwell |
| S2 | Precedence switches source with the same value/confidence | Stable route fingerprint changes; new fact |
| S3 | Same route and full fingerprint on another cycle | No duplicate fact |
| S4 | Unavailable output becomes available `True` | No comparison to undefined old value; ordinary `to_true` dwell |
| S5 | Pending `False` remains `False` but its source route changes | Original dwell deadline stays; fresh fingerprint published if still valid |
| S6 | Formula or quorum gains a contributing/available input without changing result | Its evaluated-input route changes and remains auditable |

**Review result:** Layer 0 owns the stable source/change fingerprint, Layer 2
owns bounded route construction and value dwell. The same rule applies to
categorical, numeric and physical boolean fusions. No V3 runtime test ran.
