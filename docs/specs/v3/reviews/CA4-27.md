# CA4-27 — composed configuration generation

**Status:** specification reviewed (2026-10-10).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decisions and exact gap

Each layer specified its own atomic swap, but no rule covered a valid edit that breaks a
downstream consumer, the order of layer swaps, terminal publication of a removed semantic claim,
or the meaning of `effective_at` after a crash. Layer 5 cited a "selective revalidation rule" that
was never defined. The developer approved: one composed generation with one durable manifest
whose write is the activation (D1/A); an impact preview with explicit confirmation bound to its
fingerprint (D2/iii); declared invalidation per layer, with a Reaction demoted and non-evaluable
until a valid successor (D3); and semantic-only upstream changes that keep dependents but list
them (D4). The developer also asked that the future Layer 6, 7 and 8 interfaces make this
explicit; those obligations are recorded in the overview's deferred-ownership section.

## Reuse and owners

Layer 0 §4.7 owns the manifest, dependency index, impact classification, confirmation check,
atomic activation, restart and code-upgrade rule. Each owning layer defines its invalidation:
Layer 2 §2.5 (existing impact actions), Layer 3 §4.1.2 (definition and artifacts), Layer 4 §8
(resolver plus terminal unavailable state), Layer 5 §4.2 (authority transition, cancelled jobs,
derived `configuration_invalid` mode, pending proposals not approvable). Reused: semantic
fingerprints, source-generation invalidation, immutable Reaction generations, the authority
transition shape, the CT-2 demotion precedent and the CA4-17 dispatch fence. Overview and recap
summarize; Layer 6/7/8 obligations are recorded there.

## Scenario review

| Scenario | Required result |
|---|---|
| Remove a Sensor used by a fusion, a learner, a resolver and a Reaction guard | One impact record with four breaking entries; nothing commits without confirmation of its fingerprint. |
| Confirmation after another edit committed | Base generation mismatch rejects; fresh preview required. |
| Confirmed commit | One manifest; learner invalid, resolver emits one terminal unavailable fact, Reaction `configuration_invalid` with jobs cancelled; no cycle mixes generations. |
| In-flight multi-call step of the invalidated Reaction | Dispatch fence rejects unsent calls; sent calls are not compensated. |
| Only the Sensor's reliability changes | Semantic-only entries; Reaction keeps generation and authority; learner artifacts become unavailable via fingerprint. |
| Crash before / after manifest write | Old / new composition after restart; no partial generation. |
| Code upgrade invalidates a committed formula dependent | Bootstrap applies the invalidation under the system actor and reports it. |
| Successor Reaction configuration validates | Starts `notification_only`; promotion and consent are required again. |

This is document-level evidence; no V3 runtime test has run.
