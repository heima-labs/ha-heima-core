# CA4-152 — recovery state precedence

**Status:** specification reviewed (2026-10-22).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** CA4-151 entry/exit rules; §7.4 reconciliation gate (confirmed episode and
  left `degraded_recovery`/`recovery_settling`); `FrozenRecoveryView` carries state and episode id
  separately; CA4-55 single meaning per state; Layer 8 §5.2 banners.
- **Gap.** No precedence when several entry conditions hold in one cycle.
- **Overlap check.** No new type or field; the episode id already exists.
- **Owners.** Layer 0 §7.1, §13; Layer 8 §5.2 banner row.
- **Responsiveness.** One comparison in the O(1) classification.

## Decision (developer-approved 2026-10-22)

`startup_recovery` > `degraded_recovery` > `power_recovery` > `recovery_settling` > `normal`, with the
power episode recorded regardless of the shown state.

## Scenario review

| Scenario | Result |
|---|---|
| Startup window still open, power evidence seen | `startup_recovery`; episode minted. |
| After startup: power evidence and 50 % members unavailable | `degraded_recovery`; episode id present; no reconciliation. |
| Degraded condition clears | `recovery_settling`; then `normal` after 120 s; §7.4 reconciles once. |
| Power evidence, members readable | `power_recovery`, then `recovery_settling`, `normal`, reconciliation. |
| Degradation during an open episode | `degraded_recovery`; same episode id; back to `recovery_settling` afterwards. |

Textual review only; no V3 runtime test has run.
