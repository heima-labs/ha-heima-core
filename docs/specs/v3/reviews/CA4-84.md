# CA4-84 — connection access type removed; opening display name

**Status:** specification reviewed (2026-10-13).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision

`ResolvedConnection.access_type` is removed: it had no V3 source and no V3 consumer. `Opening`
gains `display_name: str | None`, presentation metadata excluded from the Topology fingerprint.

## Overlap check

Connections stay derived from passable openings; no authored `Connection` exists. The name follows
the same metadata rule as `Room`, `Zone`, `Sensor` and `Actuator` display names.

## Scenario review

| Scenario | Result |
|---|---|
| Opening renamed | No fingerprint change; panel and notifications show the new name. |
| Opening without a name | Shown as a composed, translated label (type, orientation, room). |
| Serialized topology containing `access_type` | Rejected as an unknown field. |

Textual review only; no V3 runtime test has run.
