# CA4-95 — completing the Reaction lifecycle

**Status:** specification reviewed (2026-10-14).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decisions (approved)

- **V1.** The commit that invalidates a Reaction's generation emits one `available=False` fact for
  its decision claim, as removal does; the next valid evaluation after a successor writes a new
  value.
- **G2.** A change-set `replace` with the unchanged canonical configuration is a revalidation for
  admin-direct and learner-origin Reactions. It recompiles the plan against the current
  composition and, if valid, ends `configuration_invalid` with a successor in `notification_only`.
  For learner-origin Reactions it is not a semantic edit (restore rule of CA4-90) and needs no new
  proposal. It is a Layer-5 staging contribution distinct from `stage_admin_direct_reaction`.
  Layer 8 offers a "revalidate" action.
- **G4.** Invalidation, removal and a configuration successor, like disablement and revocation,
  emit no follow-up and block a terminal call.

## Lifecycle check

| Transition | Owner |
|---|---|
| Creation: admin-direct change set, proposal acceptance | Layer 5 §4.1–4.2 (CA4-87) |
| Rename | Layer 5 §4.2 (CA4-85, CA4-91) |
| Edit → successor in `notification_only` | Layer 5 §4.2 |
| Promotion, consent, revocation, disablement, re-enablement | Layer 5 §4.2 |
| Invalidation by an upstream change, with decision state | Layer 5 §4.2, §5.2 (V1) |
| Exit from `configuration_invalid` | Layer 5 §4.2 (G2) |
| Removal and restore | Layer 5 §4.2 (CA4-90) |
| Restart | Layer 5 §3.2, §6.0; Layer 6 §11 |
| Successor during a running activation | Layer 5 §6.0 (G4) |

## Alternatives rejected

- Automatic revalidation at each commit: contradicts "invalid until an administrator commits a
  successor", and the plan fingerprint includes producer generations, so a system-created
  successor would be needed anyway.
- No exit (remove and recreate): loses the Reaction's operational continuity and history link.

## Overlap check

No new type, command or state: reuses the change-set `replace`, the restore identity rule, the
terminal-unavailable rule and the existing follow-up exclusions.

## Scenario review

| Scenario | Result |
|---|---|
| Sensor removed: dependent automatic Reaction invalidated | Authority disabled, jobs cancelled, one `available=False` decision fact, entity `invalid`. |
| Sensor re-added; administrator revalidates a learner-origin Reaction | Successor in `notification_only`, no new proposal; promotion and consent needed again. |
| Revalidation while the upstream is still missing | Preview error; nothing committed. |
| Successor committed during a running activation | Jobs cancelled, holds invalidated, no follow-up or terminal call. |
| "Why" query after invalidation | Decision state unavailable since the commit; earlier values from history. |

Textual review only; no V3 runtime test has run.
