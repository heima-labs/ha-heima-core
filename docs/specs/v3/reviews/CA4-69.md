# CA4-69 — actionable consent and advisory feedback

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved with C2)

Two new response owners in Layer 0's ingress: `layer5.household_consent` and
`layer5.advisory_feedback`. Proposal review and disabling an automation stay non-actionable.

## Overlap check

Consent reuses `HouseholdConsentAuthority` and the exact `set_reaction_household_consent`
transition and precondition: one authority rule, two entry paths. Feedback is a new
non-authoritative event fact, distinct from `actuator.correction` (an observed resident override)
and from any governance record; it feeds only the already planned presentation-preference model.

## Scenario review

| Scenario | Result |
|---|---|
| Authorized resident taps grant | Same authority transition as the command; request closed `granted`. |
| Non-authorized resident taps grant | Rejected by the owner; nothing changes. |
| Tap after the request closed | Rejected at ingress (withdrawn request). |
| Decline | No authority change; request closed `declined`. |
| Advisory marked not useful twice | One feedback fact. |
| Advisory ignored | No fact; censored for learning. |
