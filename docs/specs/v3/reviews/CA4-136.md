# CA4-136 — consent authority before Person removal

**Status:** specification reviewed (2026-10-21).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 5 §4.2 command 7 is an immediate governance action with one
  disposition per current consent; Layer 0 §4.7 keeps authority transitions out of configuration;
  Layer 8 §6.1 lists consent-authority changes as immediate; Layer 5 §7.1.1 and Layer 2 §2.8 treat a
  referenced Person's removal or reclassification as an authority removal.
- **Gap.** The rule required the authority change inside the Person's change set, which an
  immediate action can never be (audit F-L5a-03, F-L8-01).
- **Overlap check.** Reuses command 7 and its dispositions; no new edit kind or record.
- **Owners.** Layer 5 §7.1.1, §8; Layer 2 §2.8, §9; Layer 8 §6.3, §16.

## Scenario review

| Scenario | Result |
|---|---|
| Reclassify a resident holding consent authority to `guest` | Staging rejects; preview names "Remove from consent authority first". |
| Command 7 removes that resident with retain/revoke per consent | Applied immediately; revocations cancel future jobs. |
| Same Person edit afterwards | Validates and commits; dependents listed in the impact record. |
| Remove a Person without consent authority | Ordinary edit; no extra step. |
| HA user cleared for an authority holder | Rejected until authority removed. |
