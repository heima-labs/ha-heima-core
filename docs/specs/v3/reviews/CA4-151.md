# CA4-151 — recovery classification rule and observation set

**Status:** specification reviewed (2026-10-22).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 0 §7 pre-DAG Recovery classification and its consumers (§6.3 hold
  observation boundary, §7.4 reconciliation gate, Layer 5 `FrozenRecoveryView`, Layer 8 banner);
  CA4-55 single meaning of `degraded_recovery`; Layer 2 per-`FusionRule` `min_available` gates as a
  separate local granularity; pushed Layer-2 projections (§7.4 policy, CA4-145 role projection);
  core-fixed versioned bounds (2 h escalation, 24 h confirmation).
- **Gap.** No countable rule for `degraded_recovery`/`recovery_settling`/startup/power pattern and no
  owner for the critical-entity allowlist.
- **Overlap check.** `RecoveryObservationSet` replaces the unowned allowlist rather than adding a
  second list; membership reuses `power_recovery_policy` and adds one Sensor field. The rule reads
  only Layer-1 `available` and time; no fact type is named in Layer 0.
- **Owners.** Layer 0 §7.1–§7.3, §10, §13; Layer 2 §2.5, §3 (`Sensor.recovery_observation`); Layer 1
  §4.3 wording.
- **Responsiveness.** `|U|` and the last transition instant are maintained at intake; per-cycle
  classification is O(1); no I/O.

## Decisions (developer-approved 2026-10-22)

1. Option A: Layer 2 declares the set; Layer 0 owns a meaning-free rule.
2. Initial values as listed in Layer 0 §7.1, provisional, to be recalibrated after live inventory.

## Scenario review

| Scenario | Result |
|---|---|
| Zigbee coordinator lost, 8 of 12 members unavailable | `degraded_recovery`; §7.4 waits. |
| Coordinator back, all available | `recovery_settling`; `normal` after 120 s stable. |
| One battery sensor dead permanently | Never degrades a 12-member set; settling ends. |
| Small house, 1 observed member lost | No global degrade; local gates apply. |
| Restart, UPS sensor reports off→on | `power_recovery`; episode minted; reconciliation after settling. |
| Restart without power sensor, 3 of 4 baselined members changed | `power_recovery` by pattern. |
| Plain process restart, all members unchanged and fresh in 3 s | `startup_recovery` → `recovery_settling` → `normal`. |
| Generation adds members | Rules re-evaluated against the new set. |
| Second power-evidence Sensor staged | Rejected. |

Textual review only; no V3 runtime test has run.
