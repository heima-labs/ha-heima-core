# F-L0-06 — hold-audit continuity correction

**Impact record (before normative edit, 2026-10-20).** CA4-38 already approves a bounded queue and durable `queue_overflow` loss declaration before the continuity watermark may pass a discarded event. Layer 0 §4.4 states this rule; §4.6 applies it to hold-audit facts. Layer 0 §6.4 and §13 currently restate only the successful-write branch, leaving a valid discarded hold-audit fact able to block the watermark forever if those sentences are read alone.

**Reuse and scope.** Reuse the existing ordinary event queue, per-stream/global `queue_overflow` gap boundary, and §4.4 watermark accounting. Correct Layer 0 §6.4 and its §13 acceptance criterion, plus the overview and recap summaries that say all writes must be acknowledged. Registry owner: Layer 0 §6.4, depending on §4.4, §4.6 and the state-history identity. CA4-38 remains the approved policy; this correction introduces no new product choice.

**V2-to-V3 constraint.** The shared Layer-0 mechanism must work for lifecycle audit on a light, HVAC channel, or future valve without a hold-specific journal, synchronous write, or relaxed live hold admission. An invalid audit value that never entered the queue remains a §4.4 continuity blocker; queue overflow cannot declare it lost as a queued fact.

**Counterexamples to reject.** A light hold audit discarded before its gap is durable must not permit a watermark advance. An HVAC hold audit whose gap becomes durable must not wait forever for an impossible fact receipt. A valve audit construction failure must not be mistaken for queue overflow. No case may treat a discarded fact as written or infer an absent hold from an incomplete audit stream.

## Semantic scenario review

| Case | Expected result under Layer 0 §4.4/§4.6/§6.4/§13 |
|---|---|
| Valid light hold audit, successful durable write | Fact acknowledgement resolves the queue item; the watermark may advance once all earlier obligations are resolved. The live hold took effect independently. |
| Valid HVAC hold audit, write pending or failed | The item remains unresolved; watermark stays before it. A crash uses the last acknowledged watermark and process gap. Live admission remains in force. |
| Valid light or HVAC hold audit discarded by ordinary overflow, gap write pending | No fact receipt exists; watermark stays before the loss until the per-stream `queue_overflow` boundary is durable. Historical reads requiring that audit stream are incomplete over the loss. |
| Same loss after its gap boundary is durable | The discarded item resolves as declared loss for accounting; watermark may advance if other obligations allow. The fact is never counted as written and the audit interval remains incomplete. |
| Valid audit discarded during a global overflow epoch | Its loss is covered by the durable global opening; the open epoch keeps historical coverage incomplete. Closure follows §4.6 accounting, independently of unseeded state keys. |
| Valve audit value fails runtime shape construction before queue admission | The live hold remains effective; the known transition instant blocks the watermark under §4.4. No `queue_overflow` receipt can resolve a fact that never entered the queue. |
| Exact retry or concurrent later audit transition | Same operation id and canonical payload coalesce; distinct transitions retain distinct obligations. A later receipt cannot settle the earlier pending audit or its loss declaration. |
| Orderly stop with a pending audit or loss boundary | The drain must acknowledge all accepted items or their declared losses through its final barrier; otherwise restart uses the hard-crash boundary. |

**Review result:** the corrected owner, acceptance, overview and recap agree with CA4-38 and Layer 0 §4.4/§4.6. The rule is generic across channel kinds and does not alter live hold admission. This is textual contract and scenario evidence. **Executable/runtime test:** not run for this documentation correction.
