# CA4-15 — envelope identity review

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact

Layer 3 §6.5 defines `CoverageCell` with both axis values and evidence fields
(`support`, `calibrated`). §6.4/§6.6 and Layer 5 §4.1 use a semantic candidate
fingerprint that must survive a compatible evidence refresh. Hashing complete
cells would change identity when support changes. Comparing complete cells also
breaks exact current-context membership and subset checks. Root
`descriptor_parameters` appear in the §6.4 identity list but are omitted in
§6.6.

Reuse the existing canonical envelope and candidate; define one pure semantic
projection of axes and canonical cell keys (axis values). Keep support and
calibration in review evidence, not in identity. An added/remapped cell changes
semantic identity, while support-only changes do not. Apply the same projection
to Layer-5 validation and `bounded_adaptive` subset checks.

| ID | Scenario | Required result |
|---|---|---|
| S1 | Cell support rises from 10 to 20 with the same axes and key | Same candidate semantic fingerprint; review evidence refreshes |
| S2 | New cell key or changed axis partition | New semantic projection; ordinary compatibility check applies |
| S3 | Root descriptor parameter changes | New candidate semantic fingerprint |
| S4 | Current cell has matching key but different stored support | Exact runtime membership succeeds by key |
| S5 | Later envelope drops a cell after approval | Subset comparison uses keys, subject to separate CA4-14 adoption lifecycle |
| S6 | Two cells share one key | Staging rejects the ambiguous envelope |

**Review result:** Layer 3 §6.4–6.6 and Layer 5 candidate validation now
identify the same semantic projection. This does not resolve the separate
revision/adoption lifecycle in CA4-14.
