# CA4-90 — Reaction removal lifecycle

**Status:** specification reviewed (2026-10-14).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved, S5 of the CA6 reread)

- Removal drops the Reaction's catalog entry in an ordinary composed commit and applies the
  existing invalidation effects of Layer 5 §4.2 (authority disabled, future jobs cancelled).
  Every other effect follows existing revocation and configuration rules; the decision claim gets
  one terminal `available=False` fact.
- Root, generations and transitions remain as history; a `reaction_id` is never reassigned.
  Restore appends a successor generation to the same root in `notification_only`, inheriting no
  authority, consent or adoption.
- Learner-origin Reactions may be removed (S5.1a); their restore must equal a committed
  configuration, so it is never a semantic edit.
- A pending artifact-adoption proposal naming a generation that is replaced or removed closes in
  that commit as `proposal_incompatible` with the new transition code
  `target_generation_not_current` (S5.2a, extended to the superseded-generation case).

## Alternatives rejected

- Archiving (disabled plus hidden flag): dead catalog entries, occupied names, surviving entities.
- Physical deletion of root and history: breaks history, restore and explanations (CA4-78).
- Leaving stale adoption proposals pending: never resolvable, clutters review.

## Overlap check

Reuses invalidation (Layer 5 §4.2), revocation effects (advisory/consent `authorization_disabled`,
hold `authority_revoked`, managed-episode closure, recovery filtering), `binding_deactivated`, the
terminal-unavailable rule already used by Layers 2 and 4 for removed producers, and the existing
`proposal_incompatible` disposition. One new closed value: `target_generation_not_current`, since
no existing transition code describes a target generation that can never become current.

## Scenario review

| Scenario | Result |
|---|---|
| Remove an `automatic` Reaction with a running activation | Authority disabled, jobs cancelled, no follow-up or terminal call. |
| A channel held by that Reaction | Hold invalidated `authority_revoked`. |
| Open advisory or consent request | Closed `authorization_disabled`; notifications cleared by Layer 6. |
| Open managed episode, then restart | Episode closed at removal; no resumption proof. |
| Recovery baseline facets of the Reaction | Filtered; surviving direct facets unaffected. |
| "Why" query for a time before removal | Decision state reconstructed from history. |
| Restore the removed Reaction | Successor generation, same root, `notification_only`. |
| New Reaction after removal | Receives a new id, never the removed one. |
| Pending adoption proposal on the removed Reaction | `proposal_incompatible`, `target_generation_not_current`. |
| Successor generation appended while an adoption proposal is pending | Same closure in that commit. |
| Remove a learner-origin Reaction, then restore | Restored configuration equals the committed one; allowed. |

Textual review only; no V3 runtime test has run.
