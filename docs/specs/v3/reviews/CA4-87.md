# CA4-87 — proposal acceptance commits a composed generation

**Status:** specification reviewed (2026-10-13).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved, S2 of the CA6 reread)

Accepting a learned proposal stays an immediate governance command and commits one composed
generation (Layer 0 §4.7): the new Reaction in `notification_only`, its catalog entry with an
optional `display_name`, and its disabled availability bindings, together with the `accepted`
review transition in the same transaction. Its impact record is empty because a new consumer
breaks nothing, so no confirmation is needed. `stage_admin_direct_reaction` and
`stage_comfort_trajectory_prerequisite_generation` are Layer-5 staging contributions of the
Layer-8 change set, effective only at its commit.

## Alternatives rejected

- Acceptance as a change-set edit: makes review half configuration and half governance (rejection
  stays immediate), lets a proposal go stale inside a session, and contradicts L8-C4.
- Two-phase acceptance with a "pending" Reaction activated by a later commit: state outside any
  generation.

## Overlap check

No new type, field or rejection code. Reuses the Layer 0 §4.7 commit and its empty-impact rule,
the existing writing of Layer-5 records in the manifest transaction (dependent invalidations),
`GovernanceCommandResult` with `validation_failed`, the CA4-85 catalog and name rule, and the
Layer 8 §6.4 rebase. Artifact-adoption acceptance creates no configuration and is unchanged.

## Changes

| Place | Change |
|---|---|
| Layer 0 §4.7 | Catalog listed; acceptance is the one governance command committing a composed generation; review transition in the commit transaction. |
| Layer 5 §4.1 | Acceptance stages Reaction, catalog entry and bindings; one transaction; name collision rejected, proposal pending. |
| Layer 5 §4.0, §4.2, §7.1.1 | Command 1 and the prerequisite input are change-set staging; result `resulting_ref` set at commit; command 2 may name the Reaction. |
| Layer 5 §8 | Acceptance criterion. |
| Layer 8 §6.1 | Acceptance is the one immediate action that creates configuration; open change set rebased. |
| Recap | Acceptance commits one composed generation. |

## Scenario review

| Scenario | Result |
|---|---|
| Accept with a free composed name | One commit, empty impact, Reaction `notification_only`, bindings disabled. |
| Accept with a colliding composed name | `validation_failed`, no mutation, proposal `pending`; retry with a name applies. |
| Accept while another admin has an open change set | Generation N+1 committed; that change set is rebased at apply. |
| Crash during acceptance | Manifest, generations and review transition all present or all absent. |
| Retry with the same `operation_id` | `idempotent_replay`. |
| Payload no longer valid on the current registry | Non-approvable readiness assessment, unchanged rule. |
| Admin stages a direct Reaction in the change set | Nothing appended until the change set commits. |
| Accept an artifact-adoption proposal | Adoption transition only; no composed generation. |
