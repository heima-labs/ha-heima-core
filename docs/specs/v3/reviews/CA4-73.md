# CA4-73 — Layer-6 inputs: response request ids, binding descriptor, generation contents

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved, U1–U4 of the Layer 6 draft)

- **U1:** `ConsentRequestOccurrence` and `ReactionAdvisoryOccurrence` carry `response_request_id`.
  A consent still pending at process start gets a fresh ingress request and a `reissued` phase.
  A `decline` from any authorized resident closes the request for the household.
- **U2:** Layer 5's availability binding declaration names `reaction_descriptor_id`.
- **U3:** Layer 0 §4.7 includes recipients and family options in the Layer-6 generation; they have
  no dependents.
- **U4:** `HouseholdConsentAuthority` references are HA user ids.

## Overlap check

No new type or owner. `reissued` extends an existing occurrence; the request id is the one Layer 0
already mints. Durable ingress declarations were rejected to avoid changing Layer 0, which is in
development. The descriptor id is an existing fact about the Reaction; the family decision stays
in Layer 6.

## Scenario review

| Scenario | Result |
|---|---|
| Consent opened, two authorities notified, one declines | Request closed `declined`; both notifications cleared. |
| Consent opened, restart, authority taps the old button | Ingress rejects the withdrawn id; the `reissued` notification replaced it with a new id. |
| Consent opened but undelivered (quiet hours), restart | Opening record retires undelivered; `reissued` is delivered when quiet hours end. |
| Advisory opened | Occurrence carries the feedback request id; buttons use it. |
| Weather-protection binding with a held window | Layer 6 sees a `safety.*` descriptor and uses the `safety` family. |
| Only recipients edited | Empty impact record; no confirmation. |

Textual review only; no V3 runtime test has run.
