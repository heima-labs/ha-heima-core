# CA4-116 — personal notification preferences

**Status:** specification reviewed (2026-10-17).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 6 §5.1 recipient model (administrator-configured, `locale` on the
  recipient), §5.3 no silent drop, §6.2 quiet hours with the household silent option, CA4-77 open
  actionable phases never silenced, §7.5 retirement causes, §8.2 locale, §10 generation without
  dependents; Layer 8 §4 roles, §5 sections, §13 catalog, §9.2 layout store pattern.
- **Gap.** No resident self-service: language, family muting and endpoint choice required an
  administrator configuration change.
- **Overlap check.** `quiet_silent` is the §6.2 silent rule applied to one person; it combines with
  `silenced_families`, the most restrictive winning. `locale` moves from `NotificationRecipient`,
  no duplicate. The store follows the map layout pattern (immediate save, revision). An opt-out is
  an explicit rule, distinct from unreachability, so it never triggers the fallback.
- **Owner.** Layer 6 §3, §5.1, §5.3, §5.4, §6.2, §7.5, §8.2, §10, §11, §12, §14; Layer 8 §5, §13.

## Decisions (developer-approved)

1. Personal language, per-family level (`default`, `quiet_silent`, `off`) for `attention`,
   `suggestion`, `governance`, and enabling/disabling own endpoints with at least one kept.
2. Open actionable requests and `safety` are never filtered; audiences and new endpoints stay
   administrator decisions.
3. Layer-6 preferences store outside the composed generation; immediate save with revision check.
4. The person edits their own recipient; administrators edit any.
5. Every recipient opted out: retired with cause `recipient_preferences`, no fallback, warning to
   administrators.
6. Personal quiet-hour schedules deferred.

## Scenario review

| Scenario | Result |
|---|---|
| Resident mutes `attention`; window held open at night | Others get it in the morning; the resident never. |
| Every resident mutes `attention` | Retired with `recipient_preferences`; administrators warned; no persistent notification. |
| Resident mutes `governance`; consent request opens | Request still reaches the resident (open actionable). |
| Weather protection acts at night | `safety` reaches everyone. |
| Resident disables the tablet endpoint | Phone only; disabling the phone too is rejected. |
| Administrator removes the phone endpoint, tablet disabled | Disabled set ignored, tablet used, diagnostic raised. |
| Resident edits another person's preferences | Rejected. |
| Italian resident in an English household | Italian text; fallback still in the household locale. |
