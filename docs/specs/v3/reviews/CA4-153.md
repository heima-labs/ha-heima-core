# CA4-153 — fact value contracts and Formula validator inputs

**Status:** specification reviewed (2026-10-24).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 2 §5.3 formula compile/validate split and the reject-at-staging rule;
  numeric hysteresis and difference unit requirements; Sensor `unit_contract`; Layer 0 §4.7 breaking
  classification by value type/unit/vocabulary; Layer 4 `SemanticOutputTemplate` and
  `SemanticInputSchema` value/unit; Layer 7 `value_contract`; Layer 2 runtime non-bool diagnostic.
- **Gap.** No defined claim value contract and no validator input for it.
- **Overlap check.** Layer 7's untyped `value_contract` and Layer 4's "value vocabulary/unit" are the
  same concept; both now use the one Layer-1 type. No second registry is added: contracts are derived
  in the existing staging pass.
- **Owners.** Layer 1 §3; Layer 2 §2.3, §5.3, §9; Layer 0 §4.7; Layer 4 §4.1; Layer 7 §3.
- **Responsiveness.** Staging only; no runtime lookup or new hot-path field.

## Decision (developer-approved 2026-10-24)

Option A: derived `FactValueContract`, passed to the Formula validator and reused by Layers 0, 4, 7.
