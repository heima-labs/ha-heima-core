**Status:** CA4-13 is specification-reviewed (2026-10-07); CA4-14 is specification-reviewed in
[its separate record](CA4-14.md).
**Evidence type:** `textual_contract_and_scenario_review` — contract and backlog review plus developer decisions.

## Room-return timing slice (2026-10-06)

**Approved decision:** use the already specified `RoomOccupancySurvivalModel.return_delay`
as the first operational learned-delay target. The model estimates time from a resolved
room `present -> absent` transition to the next `absent -> present` transition; it does
not predict an Actuator state or issue a command. The common Reaction timer, authority,
hold, guard and ApplyStep path remains generic across Actuator kinds. A current return
to `present` cancels a pending vacancy action. Layer-2 vacancy stability and the
Layer-5 delay are separate additive spans.

**Exact gap:** Layer 3 currently marks this survival result diagnostic-only and starts
its grid at five minutes. Layer 5 currently accepts only the scalar
`FutureStateFractionOutcome` in `ReactionTimingModelBinding`; its routine descriptor
has no delayed path. Reusing the fraction result would misstate a first-return
cumulative incidence, particularly with an `away` competing event.

**Reuse and ownership:** Layer 3 §4.4.1 supplies the typed survival result, censoring,
baseline and ML quality gates; Layer 5 §§3.2, 4.2, 6.0, 7 and 8 supply descriptor
registration, immutable timing binding, timer, fresh admission and acceptance.
Layer 4 §9.1 owns the resolved room-occupancy state; Layer 2 §5.2 owns vacancy
debounce. Layer 0 §3.1/§3.2 owns ephemeral jobs and `LearnedWindow`. CA4-14 already
owns artifact adoption. The overview, recap, backlog and registry follow this slice.
The V2-to-V3 constraint is one typed Reaction/action path, with no lighting-specific
executor or history read during evaluation.

**Cross-kind counterexamples:** delaying a light-off may avoid a needless cycle, but
delaying a safety-relevant valve closure cannot be inferred from the same room-return
probability. A mixed bundle cannot inherit one deadline if one member is urgent.
A returning resident cancels the vacancy occurrence even if its timer has become due.
An `away` transition is a competing event for training, not a fabricated return.
A sensor gap can be credited to a live timer only under its declared gap semantics;
the corresponding learning interval remains censored. An unavailable or withdrawn
artifact uses the staged seed, never a stale curve. A process restart discards the
old activation and job.

**Room-return slice result:** Layer 3 now permits an action-serving validated
`return_delay` result with a one-minute first horizon; Layer 5 has a distinct
survival selector `d=min+(max-min)*P(return by max)`, the optional
single-member `routine.actuation_bundle` vacancy path, seed fallback, one
trigger-driven replacement job and fresh admission. This is a specification
and scenario review only; no V3 runtime or executable test ran. The
translation permission below closes the remaining generic admission gap.
Neither the solar-fraction
exploration nor the generic fraction fixture is an Initial-V3 timing model.

### Generic delayed-target admission decision (2026-10-07)

**Approved direction:** a light is an ordinary registered Actuator. The
room-return timer is not limited to `light_state`; the developer declares
delay eligibility on a versioned Layer-5 intent-to-target translation entry.
The administrator stages a Reaction using that permission and bounded
`LearnedWindow`, without configuring a new property on every Actuator.

**Exact gap:** §7 currently says a `member_validator` needs an explicitly
deferrable intent/target but defines neither the registration shape nor how
staging and due-time revalidation find it. With no entry specified, the
Initial-V3 path is closed even for a valid generic Actuator. Replacing this
with a hard-coded `light_state` allowlist would conflate the first example
with the common mechanism.

**Reuse/owners:** Layer 5 §6.0 already has the closed core translation table
indexed by intent, channel kind and adapter, the typed `ChannelTarget`,
complete affected-facet validator, common admission reasons and versioned
plan fingerprint. §§3.2/4.2 own descriptor path and configuration identity;
§7 owns the one-member vacancy use. Layer 0 owns `LearnedWindow` bounds;
Layer 2 owns only the Actuator channel registry. Overview, recap, backlog,
Layer-5 acceptance and the contract registry follow. The V2-to-V3 boundary
remains one Actuator-neutral translation and ApplyStep path, without a
second device-specific timing pipeline.

**Cross-kind checks:** a light power-off target may be eligible if its exact
translation declares this permission; a valve-position target must not
inherit permission from the light or from being a room Actuator. A fan with
two target variants may allow one and reject another. A generic switch's
display role and HA domain give no permission. A mixed bundle with an
ineligible member cannot partially wait or dispatch. Adapter rebinding,
changed target facets, missing permission, a shorter permission maximum,
revoked authority or a hold still block a delayed command.

**Reviewed registration result:** Layer 5 §6.0 now gives each frozen core
intent/channel/adapter translation entry an optional versioned
`TranslationDelayPermission` with an exact timing path, typed target
validator and positive maximum delay. The immutable Reaction plan retains
the selected permission id. Staging rejects an absent permission, target
outside its envelope or configured delay beyond its maximum; due-time
retranslation repeats that check. Changing the permission meaning requires
a new id/version and successor Reaction review. The Initial-V3 descriptor
cannot bootstrap with zero eligible translation entries, but the normative
rule does not enumerate device kinds: the developer's core translation
registry publishes the concrete supported targets. No administrator or
learner can invent a permission. Each permission asserts that every target
it accepts may safely wait its full maximum even when the model chooses a
shorter wait; a safety deadline cannot be inferred from return probability.
This is specification evidence, not a
claim that V3 translation entries or runtime tests have been implemented.

## Current CA4-14 adoption slice

**Approved:** proposal evidence names each supplemental artifact with a typed,
role-tagged reference; the adopted revision belongs to a separate durable
adoption record, never to the immutable Reaction configuration fingerprint.
The ordinary Layer-3 validation/shadow, Layer-5 review, notification-only,
admin promotion and descriptor-required resident consent gates still apply.
`pinned` requires an administrator to review each new revision;
`bounded_adaptive` can advance only within its pre-authorized compatibility
envelope. This decision applies beyond the solar example.

**Resolved pinned contradiction:** Layer 3
§4.9 calls for a new Layer-5 reviewable proposal per pinned artifact revision,
but Layer 5 §4.1 makes accepted proposals terminal and deduplicates candidate
proposals by semantic configuration rather than artifact revision. Refreshing
the accepted proposal is forbidden; resubmitting the same semantic candidate
returns the old proposal. The developer approved a revision-specific
`ReactionArtifactAdoptionProposal` for the existing Reaction. Its identity
includes the artifact revision; acceptance through `review_proposal` appends
an adoption transition without creating a new Reaction or changing authority.

**Affected contracts:** Layer 3 §§4.9 and 6.2–6.4 (candidate evidence and
adoption mode); Layer 5 §§4.1–4.2 and 8 (proposal/adoption records and
acceptance). Layer 5 §6.0 consumes only a currently eligible adopted
revision. Overview, recap, backlog and registry follow this bounded slice.
The V2-to-V3 constraint is to keep one reviewed
candidate/configuration path and avoid a second command or consent path.

**Counterexamples:** a pinned room-light model receives two compatible
revisions with identical Reaction parameters; they still need distinct admin
decisions. A bounded-adaptive solar-cover model receives a revision that adds
an unapproved operating-envelope cell; it cannot auto-adopt. A diagnostic-only
model has no `ConfiguredReaction`, so its adoption record cannot require a
Reaction id. A crash during an adoption write must expose exactly the old or
new committed revision, not a pointer to absent evidence. An expired or
withdrawn adopted artifact cannot influence a pending timer; Layer 5 uses the
authorized seed and reevaluates from the original occurrence anchor.

**Scenario review for the action-bearing adoption slice:**

| Case | Contract result |
|---|---|
| First eligible timing artifact at Reaction creation | Exact revision and admin-selected mode commit with notification-only configuration; no action authority is granted. |
| Reaction begins on seed | No adopted revision is inferred; first selection requires review. |
| Two pinned revisions with identical semantic parameters | Two revision-specific adoption proposals; each accepted revision appends one transition, without a new Reaction generation. |

| Concurrent reviews or crash during append | Only one ordered adoption head commits; a retry returns the same outcome, never a half-written revision. |

| Consent revoked before an adoption | Adoption changes no consent; dispatch remains blocked by current authority. |
| Admin enters bounded adaptation on a Reaction | Current exact artifact and approved bounds pass; only adoption mode changes, without new Reaction generation or consent. |
| Admin returns to pinned while artifact is stale | Current revision is fixed but remains unavailable for serving; no older revision is silently substituted. |
| Mode change races with compatible refresh | Both compare one adoption head; one commits and the other must re-evaluate under the new head. |

The developer confirmed the egress distinction: validated diagnostics need
no adoption; a `pinned` `InferenceSignal` revision receives Layer-3
administrative approval; action-bearing Reactions alone use Layer-5
adoption proposals. The same model may still publish diagnostics while its
signal or action artifact is not adopted. The developer also approved
mode changes as authenticated adoption transitions that retain the current
artifact and Reaction authority/consent. The completed CA4-14 scenario and
dependency audit is in its separate review record.

**Serving identity review:** `objective_id` and
`minimum_practical_delta` were already `serving_semantics` and already in the
candidate fingerprint. The broad §4.5 fingerprint wording made them appear
to invalidate the response artifact anyway. Layer 3 now separates the
artifact's analysis `definition_fingerprint` from a
`serving_generation_fingerprint`. Changing either parameter preserves the
validated response revision, withdraws an unreviewed candidate, and creates
a semantically distinct proposal if a new candidate passes. A configured
Reaction retains its approved objective until ordinary successor review.
For a signal, a serving-only edit creates a new consumer chain and must
receive current administrative adoption before emission; it does not force
retraining. This reviews the serving-only edit without changing the existing
classification of analysis-semantic parameters.

**Resolved mode-change choice:** entry to or exit from
`bounded_adaptive` is already required to be an explicit administrative
transition in Layer 3 §4.7. For an existing Reaction, the approved common
behavior is an authenticated transition on the same adoption chain, keeping
its exact currently adopted artifact, configuration generation and resident
consent. Entry into `bounded_adaptive` revalidates and binds the approved
compatibility bounds before any automatic revision; exit to `pinned` freezes
the current revision. The alternative is a new Reaction configuration
generation with fresh promotion and consent, which the developer deferred as
a possible future change. Layer 3 §4.9 and Layer 5 §4.2 now specify the
transition and reject stale heads; no mode change retrains or commands an
Actuator.

**Candidate-registry cross-check:** the original
`ProposalCandidateKindRegistry` allowed only `("reaction.descriptor", 1)`.
That would reject the newly approved pinned-adoption candidate before
review. The frozen Initial-V3 registry now also admits
`("reaction.artifact_adoption", 1)` with a closed four-field payload.
Its `finding_id` resolves the immutable validation/shadow assessment for
that exact artifact; it is not an administrator-visible diagnostic finding.
The registry still rejects unknown kinds and plugin-defined candidates.

## Decisions already made

- A typed Reaction trigger may lead to an immediate step or to a delayed step. Delay is a
  common Layer-5 capability, not an occupancy or lighting-only engine. The descriptor
  declares whether a particular trigger/intent path may use it and what makes its
  activation continue. Layer 0 `Window` and `AtJob` remain the duration and scheduling
  primitives. At due time Layer 5 makes a fresh decision and performs ordinary admission;
  neither the timer nor the end of a hold sends a stored command.
- Layer 3 owns training and validation; Layer 5 owns the versioned, descriptor-authorized
  choice of effective delay within staged bounds. `LearnedWindow` retains its seed and
  bounds. An unavailable or inapplicable model uses the authorized seed. Learning does
  not run in a pure FusionRule, SemanticResolver, or Reaction evaluator.
- A time-to-event profile that must resolve short delays has a first declared horizon
  of one minute, subject to evidence and calibration at that horizon. This does not
  automatically change the separate five-minute floor for interval-sampled anchors.
  Layer-2 sensor/fusion stability and Layer-5 step delay remain separate elapsed spans;
  their end-to-end latency is stated as their sum.
- A change in the effective, authorized delay source recalculates a pending, unexecuted
  step from its original episode anchor. The old `AtJob` callback is invalidated. A due
  time now in the past requests immediate fresh evaluation, never blind replay. An
  incompatible artifact cannot be adopted automatically under the same authority;
  ordinary review/generation rules apply. A completed step is not replayed.
- The room-return risk rule is an occupancy-triggered selector, not the general
  `LearnedWindow` formula or permission to delay every Actuator. Its now
  registered formula, model binding and single-member path are in Layer 5
  §§4.2, 6.0 and 7; the original open-question wording below is history.
- **Superseded solar-forecast exploration:** the second cross-kind delay case was measured or explicitly trusted incident solar
  irradiance -> shading cover, selected instead of humidity rise -> fan activation.
  The Layer-2 `geometry_proxy` is only a deterministic angle/orientation signal;
  transient-radiation timing requires `incident_irradiance` mode and its typed
  direct/diffuse radiation inputs. The cover cannot change those external inputs.
  Any learned wait must refine the descriptor's existing relevant minimum dwell,
  not add a second wait for the same solar persistence condition.
- **Superseded continuous-dwell and learned-solar proposal:** the earlier
  wording required continuous exposure and a learned solar delay. The current
  Layer-5 descriptor instead uses one staged fixed dwell with
  `elapsed_if_requalified` gap semantics; an observed exit still cancels, and
  a movement cooldown remains separate.
- **Superseded solar timing training proposal:** the solar timing training episode used the same staged incident-irradiance
  binding and hysteresis thresholds as the descriptor. Entry anchors; exit
  ends; gaps, incomplete retained history and changed definitions censor or
  exclude without inventing an exit. Cover movement does not end an external
  irradiance episode. Layer 3 §4.4 owns this observation projection; selector
  and adoption decisions remain open.
- **Superseded solar `q` rationale:** the effective delay was not restricted to two fixed choices. Within staged
  bounds, its selector may use validated contextual estimates of both current
  exposure persistence and recurrence of a later entry after an observed exit.
  An exit still cancels the current occurrence; recurrence starts a fresh one.
  The numerical decision objective, probability horizons and evidence gates
  have not been approved. Recurrence probability alone does not identify a
  unique delay in seconds without a declared tradeoff between delayed benefit
  and unnecessary cover movement.
- Layer 3 §4.2 defines generic `FutureStateFractionOutcome` over one typed state
  stream and a complete bounded future interval. It yields a dimensionless
  scalar in `[0, 1]`, using the existing scalar-result path; gaps exclude the
  sample. Layer 2 §5.3 now supplies the closed
  `numeric.hysteresis_condition.v1` projection for quantitative triggers,
  using its validated previous-cycle self-reference. The solar Reaction
  consumes that boolean output, with no copied thresholds; no Initial-V3
  solar-fraction learner is registered.
- A lost solar condition suspends action. Under the approved
  `elapsed_if_requalified` semantics, a valid `True` immediately before and
  on the first fresh reading after the in-process gap preserves the original
  anchor and credits elapsed gap time. A fresh `False` cancels. Layer-3
  historical samples still require complete observation and never join state
  across that gap. After process restart the existing non-restoration rule
  applies and a fresh qualifying sustained state starts a full new wait.
- The approved state-fraction selector uses a horizon equal to the authorized
  `LearnedWindow.maximum` and `q` from the matching dimensionless scalar
  result. Its single wait is `ceil(min_ms + (max_ms-min_ms)*(1-q))` in whole
  milliseconds; no extra horizon, threshold, weight or two-delay switch is
  configured. An ineligible result falls back to the valid seed. Layer-5 §6.0
  now fixes this math; model eligibility, trigger-job and adoption lifecycle
  remain open.
- The approval sequence already exists: Layer 3 validates and completes the
  core type's required shadow before a proposal is eligible; Layer 5 uses the
  ordinary `LearningProposalCandidate`/`ReactionProposal` review, creates a
  notification-only generation, applies any descriptor-declared operational
  shadow, then uses common admin promotion and resident consent. Solar shading
  requires consent under its current descriptor. No second approval workflow
  is needed for timing. The actual missing contract is the typed hand-off that
  binds one approved timing model definition/result schema to an exact
  trigger/descriptor generation and distinguishes compatible artifact refresh
  from a semantic Reaction edit (CA4-13/CA4-14).

## Exact gaps and reusable contracts

**CA4-13 bullet 1 impact check, superseded solar candidate:** Layer 3 §4.2
already defines typed anchors, complete-window `FutureStateFractionOutcome`,
point-in-time features and history exclusion. §§4.3–4.7 define both the
`PatternLearner` baseline and optional registered ML path with immutable
artifacts, chronological validation, shadow and adoption prerequisites.
§4.8.6's `EnvironmentalQuantileResponseModel` predicts an observed
action-response contrast; neither it nor the existing `solar_shading`
`RelationProfileRef` forecasts future irradiance persistence. The developer
therefore removed the proposed solar `q` profile instead of selecting an
estimator from sparse local data. No solar timing learning type, artifact or
descriptor binding is required for CA4-13. Generic future timing profiles
must still use one reviewed baseline and may register ML only under §4.6's
evidence/validation contract. CA4-47's solar-geometry producer remains its
own issue, not a prerequisite for this CA4-13 closure. The V2-to-V3
constraint remains one learning/authority lifecycle and no historical read
in a Reaction cycle.

**2026-10-06 gap-time decision and impact:** the developer chose to credit an
unobserved interval to a Reaction timer when the last valid condition before
the gap and the first fresh condition after it are compatible with that
Reaction's staged qualifying state. This is an operational decision only:
Layer 3 historical coverage remains incomplete and the gap supplies no
training label, observed transition, or proof of an uninterrupted physical
state. The earlier universal cancel/restart rule in Layer 5 §6.0/§7 and the
solar wording "continuous exposure" conflict with this decision. Reuse the
typed condition/set in `ReactionTimingModelBinding`, the existing Layer-5
evaluation-plan fingerprint, Layer-0 timing/recovery boundary and the normal
fresh-snapshot admission path. The owning sections are Layer 5 §§4.2, 6.0, 7
and §8; dependent summaries are the overview, recap and backlog. The V2-to-V3
constraint remains one generic Reaction timer contract across sensor and
Actuator kinds. Counterexamples: solar exposure can disappear and return
during a gap, room occupancy can change twice, and an event-only trigger has
no persistent state to compare; none may become a Layer-3 sample or a
synthetic trigger edge. A stale callback or revoked Reaction cannot command.

**Resolved typed-state gap:** Layer 3 `FutureStateFractionOutcome` accepts one
typed state and a closed set of qualifying values. Layer 5's current
`ReactionTimingModelBinding` previously narrowed this to a boolean trigger. That covers
solar exposure but cannot directly express a room-occupancy transition into
`absent`, despite `routine.actuation_bundle` accepting typed state
transitions. A descriptor-declared qualifying-value condition would reuse
the existing outcome contract and permits both examples without an extra
boolean projection. The developer approved the typed-state contract, now
specified in Layer 5 §§4.2/6.0. Event-only triggers still need a separately declared
current continuation condition; no event becomes a persistent state by
assumption. A bundle with members needing different deadlines cannot use
one shared delayed admission.

**Resolved in-process gap-time choice:** the Reaction plan declares one of
`continuous_observed`, `accumulated_observed`, and
`elapsed_if_requalified`. The developer selected the last for solar shading:
compatible typed qualifying values before and after a gap permit the elapsed
gap to count for the Reaction timer, followed by ordinary fresh admission.
The gap remains incomplete for learning. This supersedes the initial
proposal to start every timer over. **Resolved restart boundary:** the
developer chose the established Layer-0/Layer-5 rule for ephemeral jobs and
activations. A process restart discards the anchor and pending `AtJob`; a
fresh qualifying sustained state starts a full new wait without fabricating
an edge or replaying an event. No durable timer-anchor facility is required.

**Historical CA4-13 gap before the room-return and translation-permission closure:**
Layer 0 §3.2 permits `LearnedWindow` substitutions but leaves calibration to
pure consumers. Layer 3 §4.4.1 has complete occupancy survival/censoring/validation
machinery yet marks its egress diagnostic-only and starts its grid at five minutes.
Layer 5 §5 has typed triggers, §3.2 has activation identity, and §6.0 has a stable
next-step `AtJob` slot for step-programmed Reactions, but there is no common delayed
step contract for a trigger-driven Reaction. The `routine.actuation_bundle` model is
currently immediate-only. Reuse the existing typed `RegisteredRelationProfile` output
schema and Layer-3 artifact lifecycle where applicable; do not introduce a parallel
learning or command path.

CA4-14: Layer 3 §4.9 allows `pinned` and `bounded_adaptive` artifact adoption while
Layer 5 §4.2 gives every semantic configuration edit a successor generation with
fresh authority/consent. Specify the adoption transition without silently changing
the immutable configuration, and cover diagnostic, signal and action-policy egress,
not only delayed Reactions. Layer 5 §6.0 already replaces a changed next step and
rejects stale arm revisions.

**Owners:** Layer 0 §3.2; Layer 3 §4.4.1 and §4.9; Layer 5 §§3.1–3.2, 4.2,
5 and 6.0. **Dependencies:** Layer 2 stability/retention; Layer 3 registered
profiles and historical coverage; Layer 5 descriptor catalog, hold and admission;
CA4-09 historical actuation/correction projection. **Summaries to reconcile:**
architecture overview, recap, backlog and contract registry.

**V2-to-V3 constraint:** preserve generic typed triggers and Actuator-channel actions,
one Reaction evaluator/command path, explicit authority, and bounded validated
learning. No V2 runtime or historical draft is normative for V3.

## Cross-kind scenarios to specify and review

**Gap-semantics scenario review (specification only):** a solar condition
`True` for seven minutes, unavailable for two, then freshly `True` retains
the original elapsed anchor; a nine-minute wait has reached due and requests
one fresh admission, while the Layer-3 nine-minute historical interval is
incomplete. If the returned value is `False`, it cancels. A typed occupancy
condition qualifying at `absent` can use the same declaration without a
boolean projection, but a distinct value qualifies only if its staged set
includes it. An event-only trigger cannot regain an event by endpoint
agreement. During the gap no callback commands; after return revoked
authority, a hold, failed guard or unconfirmed target still vetoes. Across a
process restart no anchor or job is restored: an unreadable first intake does
nothing, while a fresh qualifying sustained state begins a new full wait.
Event-only triggers are not recreated, and no missed due fires. At the time
of this scenario review CA4-13 still lacked publication and trigger-job
contracts; the current closure above supplies them. No executable
V3 runtime test was run.

## Historical unresolved decisions before the room-return slice

The approved selector estimates the fraction `q` of the authorized maximum
delay's future interval during which the typed condition will hold, including
re-entry after an exit. Layer 5 §6.0 fixes the linear bounded formula and
millisecond rounding. At the deadline current condition and guards remain
authoritative. The remaining work is to make the model eligible and adoptable
