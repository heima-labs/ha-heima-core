# CA4-115 — downloadable diagnostics

**Status:** specification reviewed (2026-10-16).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 8 §14 (System renders every layer's diagnostics), §13 `diagnostics`
  query (admin), §10.3 health projection; Layer 0 §10 diagnostics and §10.1 runtime error; redacted
  `FactSource`/`ApplyStepSource` and Layer 5 redacted snapshots.
- **Gap.** No downloadable file: no content definition, redaction, size bound, error behavior or
  schema stability.
- **Overlap check.** No new data: the file serializes what §14 already renders. The `diagnostics`
  query gains a `window` parameter instead of a new message; HA's diagnostics platform is a second
  entry point to the same builder; redaction reuses the owners' contracts.
- **Owner.** Layer 8 §13, §14.1, §16.

## Decisions (developer-approved)

1. One builder for the System button and HA's "Download diagnostics".
2. JSON `heima_diagnostics_v1`, one section per owner; windowed records; no raw fact history or
   learning datasets.
3. Window 24 hours by default, 7 days from System.
4. Stable in-file pseudonyms for personal data and secrets; Heima ids and `entity_id`s kept.
5. 5 MB cap, `truncated` markers, `section_error` per failing section.
6. Slow path, administrators only, available in error, recovery and without a manifest.
7. Additive keys within a schema version; a change of meaning bumps the version.

## Scenario review

| Scenario | Result |
|---|---|
| Heima in `error` because durable writes fail | File produced; runtime error section filled. |

| Busy house, 7-day window | Within 5 MB, truncated sections marked. |
| Resident tries to download | Rejected by the `diagnostics` role check. |
| Script compares two snapshots across versions | Same schema version, added keys ignored. |
