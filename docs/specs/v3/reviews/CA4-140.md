**Status:** specification reviewed (2026-10-21).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** CA4-118 `Person` registry; CA4-120 casa occupancy and household presence
  (decisions 1–6 and the values set in that pass); approved people model §3.4, invariant 1, Q2;
  Layer 2 §1 single registration, §2.4 `FusionRule` cardinality, §2.5 terminal `available=False`
  for a claim without a producer, §3.6 reserved `sun.sun` paths; Layer 3 §4.2 person-related list;
  Layer 0 §5 actor axes; Layer 8 §14.1 redaction (CA4-115).
- **Gap.** Audit group G4: F-L2-01, F-L2-02, F-L3a-02, F-X9-04, F-L8-07.
- **Verification of the removed Sensor.** CA4-120, its review and the people model require household
  presence from resident `person.*` signals, tracked residents only, guests never; none records a
  reason for a second Sensor on the same path. The `occupancy.evidence.*` namespace has no reader
  restriction that forbids the household fusion as a consumer.
- **Overlap check.** No new construct: the household fusion reuses the existing per-person fact; the
  zero-resident case reuses §2.5's terminal unavailable fact; redaction reuses the stable pseudonym.
- **Owners.** Layer 2 §2.8.1, §3 and acceptance; Layer 8 §4, §14.1 and acceptance. Layer 3 needs no
  edit.
- **Responsiveness.** One Sensor fewer per tracked resident, hence one normalization fewer per HA
  person change; diagnostics are a slow-path export.

## Decisions (developer-approved 2026-10-21)

1. F-L2-02 (and F-L3a-02): option A, one Sensor per HA person serving both fusions.
2. F-L8-07: option A, person-denoting ids pseudonymized in the exported file only.
3. Mechanical corrections for F-L2-01 and F-X9-04.

## Scenario review

| Scenario | Result |
|---|---|
| Two tracked residents, one `home` | `presence.household=True` from their person facts. |
| Guest alone at home, residents away | Guest fact may corroborate casa occupancy; presence `away`; occupancy `present`. |
| Untracked resident alone | Excluded with a diagnostic; presence `away`, occupancy `present`. |
| No tracked resident | No rule; `presence.household` one `available=False` fact with diagnostic; staging valid. |
| First resident gains a tracker | `Person` commit generates the rule. |
| Administrator adds a Sensor on `person.alice` | Rejected: path already owned by the core person Sensor. |
| Learner binds `occupancy.evidence.person.alice` | Person-related: behavior learning, censored by household context. |
| HA administrator linked to `Person(guest)` | Role `administrator` only; never `resident`. |
| Guest tablet, not an HA administrator | No role; map only. |
| Diagnostics with `recipient_id="stefano"` | Same token as the person's name, also in `occupancy.evidence.person.<id>`; panel unchanged. |
