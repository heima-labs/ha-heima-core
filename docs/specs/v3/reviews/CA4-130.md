# CA4-130 — slow-path work classes for extensions

**Status:** specification reviewed (2026-10-20).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** CA4-130 hybrid decision (shared planner, distinct class); Layer 3 §5.1
  queue, single-flight and core-owned priority; Layer 3 §5.3 envelope, cooperative slices, plan
  levels, calibration phases, health guardrails, `capacity_unknown`, external execution boundary;
  Layer 7 §7–§11 (CA4-129).
- **Gap.** The slow path knew only learning; Layer 7 referred to it neutrally; `capacity_unknown`,
  a 0–1 slot lower plan and the no-learning baseline interval had no defined meaning for extensions;
  memory and disk damage by a defective extension were unaddressed.
- **Overlap check.** No new mechanism: cooperative slices carry the priority, the existing envelope
  carries the reservation, the existing health baseline gains a class-neutral quiet interval, and the
  existing execution boundary serves the third-party isolation condition. Names were corrected
  instead of adding a second plan.
- **Owners.** Layer 3 §5.1, §5.3, new §5.3.1–§5.3.2, §9. Dependent: Layer 7 §3, §7.1, §8, §9, §10,
  §11, §13. Overview and recap need no change (neither names the plan; overview §4 still describes the
  slow path correctly).
- **V2-to-V3 constraints.** None.

## Decisions (developer-approved 2026-10-20)

1. `capacity_unknown` admits neither class.
2. Protection level A in process (pure computation, disk bounded by construction, envelope check
   between slices); out-of-process execution with operating-system limits is mandatory for
   third-party extensions.
3. Slice-level priority, serial extension runs, memory reservation of the largest enabled envelope,
   50% CPU-credit cap for the extension class.
4. Slow-path names replace learning-only names.
5. Baseline: 5-minute quiet interval for both classes, 24-hour maximum age, one forced 5-minute
   calibration window, `max_result_age >= cadence + CALIBRATION_WINDOW`, extensions start after the
   first baseline, expiry re-armed from the last persisted result at restart.

## Scenario review

| Scenario | Result |
|---|---|
| Long training, single-slot plan, extension due | Extension slice runs at the next learning slice boundary; training is paused, not killed. |
| Twenty active instances vs. one training | Extension class reaches the 50% cap; slices alternate; training advances. |
| Training admission would consume the largest extension envelope | Training deferred (`deferred_resource_pressure`, class `learning`). |
| `capacity_unknown` | No run of either class; extension state claims expire to unavailable; diagnostics. |
| Extension allocating beyond its envelope mid-run | Stopped at the next cooperative boundary; run discarded; damage bounded to one slice. |
| Extension emitting events in a loop | Run fails at `max_emissions_per_run`; no event written. |
| Extension writing a file | Forbidden by the pure-computation contract; caught in review, not sandboxed. |
| Forced calibration window with a 60-second-cadence extension | `max_result_age >= 6 min`, so no fact expires during the 5-minute pause. |
| Health incident during calibration | Sample discarded; window retried later; at most one per 24 h. |
| Busy installation with no natural quiet interval | Forced window after 24 h; baseline age reported. |
| Startup | First baseline before any slow-path work; extensions then run once with jitter; claims older than `max_result_age` unavailable at the first cycle. |
| Profile change | New plan at the scheduling boundary; class rules unchanged. |

Textual review only; no V3 runtime test has run.
