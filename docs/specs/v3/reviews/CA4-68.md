# CA4-68 — action, proposal-review and consent notices

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decisions (approved, B3–B5)

Three typed Layer-5 occurrences, each producing one reserved Layer-6 event fact through the unified
outbox, once per operation id: action notice (residents, weather protection only), proposal review
(administrators), consent request (consent-authorized residents, informative).

## Overlap check

Distinct origins from follow-up (skipped/unconfirmed decided step), availability (blocked
automation), advisory (suggestion instead of command) and recovery confirmation. The action notice
summarizes but does not replace hold availability or follow-up warnings. Reuses outbox,
`OperationalEventValue`, operation-id derivation and existing proposal and authority lifecycles.

## Scenario review

| Scenario | Result |
|---|---|
| Weather protection secures 2 channels, 1 held | One notice, three channel outcomes. |
| Solar shading completes a step | No action notice (`resident_action_notice=False`). |
| New learned proposal | One admin notice; evidence refresh adds none. |
| Proposal stale then approvable again | One `approvable_again` notice. |
| Promotion awaiting consent | One `opened` consent notice; grant or disablement closes it once. |

Textual review only; no V3 runtime test has run.
