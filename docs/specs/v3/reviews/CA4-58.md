# CA4-58 — profile output schema review

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decision and impact

The developer chose one registered, versioned policy-output schema per
`RelationProfileRef`. Layer 5 §3.1 owns the common registration and validator;
Layer 3 §4.8 publishes an artifact under that exact schema. Layer 5 validates
the referenced artifact before a descriptor interprets its typed result.
The thermal `ThermalResponseParameter` keeps its fields. Its
`ThermalEvidenceGateCalibration` is separately frozen core release metadata,
not a learner-produced parameter, and remains checked by the registered thermal
validator. The five non-HVAC environmental profiles, including
`thermal_shading`, reuse the common response-artifact
cell shape. Layer 3's `ResultEnvelope` is a per-inference result with a
closed payload union, so it cannot substitute for either the complete response
artifact or `ThermalResponseParameter`. No new action, guard, candidate or
transport pipeline is introduced.

| ID | Scenario | Required result |
|---|---|---|
| S1 | Any of `thermal_shading`, `solar_shading`, `thermal_exchange`, `air_quality_exchange`, `hygrometric_exchange` publishes its ordinary response | Common `environmental_response.v1` schema validates it |
| S2 | Thermal profile publishes a parameter under a complete core calibration | Exact thermal schema validates the parameter and eligibility |
| S3 | Artifact schema or profile version changes | Old candidate/artifact cannot be coerced into the new version |
| S4 | Future profile with a different typed output | Register its schema on the same `RegisteredRelationProfile` hand-off; descriptor owns policy interpretation |

**Review result:** owner, publication, consumption and acceptance now refer to
one registry. This review does not verify a V3 artifact implementation.
