# CA4-96 — generic numeric domain of fact payloads

**Status:** specification reviewed (2026-10-14).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved by the developer on 2026-10-13)

Source: `docs/v3/NUMERIC_DOMAIN_HANDOFF.md` in the implementation worktree. Layer 1 §3 owns one
numeric domain for every `EvidenceValue`-shaped payload: `HouseFact.value`,
`Provenance.evidence`, permitted frozen-dataclass fields and `PersistedProjection`.

- Non-boolean `int`: inclusive `[-9007199254740991, 9007199254740991]`; outside it rejected, never
  converted to `float` or string.
- `float`: finite binary64, subnormals included; `NaN` and infinities rejected; no generic range or
  rounding.
- `bool`: valid boolean payload, rejected where a quantitative number is required.
- `Decimal`, `Fraction`, `complex`: not numeric payloads; numeric strings stay strings; exact large
  values need a declared string encoding.
- RFC 8785 writes `1`/`1.0` and both signed zeros identically; stricter contracts still apply.
- Field-specific ranges, units, count semantics and confidence constraints remain.
- Invalid value: hard failure. Invalid evidence: `evidence={}` plus diagnostic.

## Changes

| Place | Change |
|---|---|
| Layer 1 §3 | "Numeric domain" replaces the numeric scalar rule; validator checks it; canonical-JSON note on `1`/`1.0` and signed zero. |
| Layer 1 §4, §4.3 | `PersistedProjection` and the evidence violation policy reference the domain. |
| Layer 1 §10 | Acceptance scenarios: limits and next values, subnormal, non-finite in nested fields, non-generic objects, numeric strings, negative zero generic versus stricter, value versus evidence failure. |
| Layer 0 §4.1 | Stored-data boundary references the domain. |
| Layer 5 §6.0 | Facet codec rejects numbers outside the domain. |

## Overlap and impact check

Layer 3's `CanonicalJsonObject` (§4.2) already used the same safe range and additionally rejects
negative zero; it is now the cited example of a stricter contract and needs no change. Layer 3's
artifact codec (non-negative safe-integer counts) is also consistent. Layer 2 static interpretation
values reach the domain through `validate_house_fact_value`; Layer 2 configuration numbers keep
their own contracts. State identity, write-on-change, the retry queue and recovery are unchanged:
they already compare canonical serializations. No serializer library, version or codec switch is
approved; CBOR remains a possible future evaluation only.

## Scenario review

| Scenario | Result |
|---|---|
| `value` contains `9007199254740991` / `-9007199254740991` | Accepted. |
| `value` contains `9007199254740992` / `-9007199254740992` | Hard construction failure; no conversion. |
| `evidence` contains `9007199254740992` | Fact kept with `evidence={}` and a diagnostic. |
| `5e-324` in a dataclass field | Accepted. |
| `NaN` inside a nested list of `value` | Hard construction failure. |
| `Decimal("1.5")` in `value` | Rejected; the string `"1.5"` is valid and stays a string. |
| `True` in a quantitative field | Rejected; valid in a boolean field. |
| `-0.0` generic / in a Layer-3 `CanonicalJsonObject` | Accepted and canonicalized to `0` / rejected. |
