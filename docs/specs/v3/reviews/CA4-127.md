# CA4-127 — rename Layer-7 "plugin" to "extension"

**Status:** specification reviewed (2026-10-20).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** CA-1 (no action authority for Layer-7 code), closed semantic registries
  (2026-09-11), LP-6 (third-party learning only through reviewed proposals), AR-8 (admin-created
  registry records). Layer 7 scope (developer-approved 2026-10-20): Initial V3 specifies only the
  boundary for first-party, in-repository extensions; third-party loading is a future option.
- **Gap.** "plugin" collides with V2 vocabulary (`register_plugin` domains, now Layer-4 resolvers;
  `LearningPluginRegistry`; fusion plugins), and `"third_party_plugin"` declares an origin that
  Initial V3 does not have.
- **Overlap check.** No new construct. `FactSourceKind` keeps its position and meaning; only the
  literal changes. "extension" was unused in the V3 layer specifications.
- **Owners.** Layer 0 §5, §5.1 (`L0-FACT-SOURCE`). Dependent wording: Layer 0 §3.4.1, §4, §4.0,
  §4.8, §5.1.3, §8, §13; Layer 2 §2.1, §3.6, §5.3, §9; Layer 3 §4.1.1, context-transform registry,
  §4.6, §4.7, thermal evidence gate, §4.9, §5.1, §5.3, §6.3.1, §9; Layer 4 §4.1; Layer 5 §2, §3,
  §3.1, §3.2, output contracts, program families, §4.0, execution audit, resident follow-up, §8;
  Layer 6 §4.1; overview §11; recap (orientation).
- **V2-to-V3 constraints.** None; no V2 code or active V2 specification changes.

## Decisions (developer-approved 2026-10-20)

1. Layer-7 code is an **extension**; `FactSourceKind` `"third_party_plugin"` becomes `"extension"`.
2. Reserved identifier namespace `ext.<extension_id>.<name>` (normative text in the Layer-7 issue).
3. A future third-party extension keeps `kind="extension"`; its origin is assigned by the loader,
   never declared (Layer 0 §5.1).
4. This slice is lexical only. Semantic corrections are deferred to the Layer-7 specification issue.
