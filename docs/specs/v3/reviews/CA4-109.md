# CA4-109 — `system.health` notification

**Status:** specification reviewed (2026-10-16).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 8 §10.3 health `error` predicate; Layer 0 §4.5: a storage failure
  leaves a notification best effort and diagnosed; Layer 6 §4.1 closed kind registry, §7.3
  fallback when no recipient is reachable, §7.4 tags.
- **Gap.** No notification for Heima's own error; predicate owned by the wrong layer.
- **Overlap check.** Reuses the kind registry, families, tags, fallback and best-effort rule. The
  predicate moves to Layer 0 (both causes are Layer-0 state) and Layer 8 references it. No new
  delivery path.
- **Dependency direction.** Layer 0 → Layer 6 and Layer 8, as for other occurrences.
- **Owner/dependents.** Layer 0 §10.1, §13; Layer 6 §4.2, §7.2, §7.4, §11, §14; Layer 8 §5.2, §10.3.

## Decisions (developer-approved)

1. Notify administrators on error and on its end; `degraded` does not notify.
2. Family `attention`, severity `error`, fixed tag, panel link.

## Scenario review

| Scenario | Result |
|---|---|
| Disk full | `error_opened` delivered once from memory, diagnosed; panel shows error banner. |
| Then configuration fails to compose | `causes_changed` with both causes. |
| Storage and configuration recover | `restored` through the durable path; replaces the message. |
| Invalid configuration at startup, storage fine | No recipients: fallback `persistent_notification`. |
| Restart with the error still present | New episode, new `run_id`; tag replaces the old message. |
| Error during quiet hours | Held until they end (`attention`), unless the family is set silent. |
| Degradation diagnostic only | No notification; yellow admin banner only. |

Textual review only; no V3 runtime test has run.
