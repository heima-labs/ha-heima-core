# CA4-61 — shared planned-absence program family

**Status:** specification reviewed (2026-10-11).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decisions and exact gap

`environment.planned_comfort_trajectory` (Layer 5 §7.1) and `security.presence_simulation`
(§7.2) each restated the same activation, continuity, exit and restart rules: planned-absence
calendar binding, effective absence as active interval plus stabilized `away`, departure and
bootstrap behavior, normal cancellation and completion, next activation, next-step hold release,
no managed-episode resumption and required consent. A change to one would have to be repeated in
the other, and a future absence program would copy them a third time. The developer approved a
closed, versioned `ProgramFamilyRegistry` with one family, `planned_absence_program` version
`"1"`, in preference to an unversioned shared section, which could silently change already
configured descriptors.

## Reuse and owners

Layer 5 §3.2 owns the family registry, the `AbsenceProgramState` result and the family rules. The
family is a pure component called by each descriptor's own `program_evaluator`; there is still
one evaluator, one administration path and one `ApplyStep` path. `CalendarPlanBinding`, the
`ReactionGuard` registry and the existing descriptor fields are unchanged. §7.1 and §7.2 now keep
only descriptor-specific behavior. Overview and recap summarize.

## Scenario review

| Scenario | Required result |
|---|---|
| Same calendar/presence trace given to both descriptors | Identical family state; only steps and targets differ. |
| Departure while running | Immediate fresh evaluation through the family component. |
| Restart during an active absence with stabilized `away` | New activation from fresh inputs; no recovered departure, hold or missed step. |
| Early committed return | `normal_cancellation` for both. |
| Calendar outage or presence unavailable | Undecidable absence; `not_ended`; future steps suppressed. |
| Missing planned-absence binding or null `Stability.to_true` | Staging rejects the declaring descriptor. |
| Future frost-protection program | Declares the family and specifies only its own steps and targets. |
| Family rule changes | New family version, adopted through each descriptor's new version. |

This is document-level evidence; no V3 runtime test has run.
