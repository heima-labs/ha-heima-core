## Findings

### F-X5-01 — `opening.open` is reserved to Layer-5 readers, so a window contact cannot also feed Layer-3 opening evidence

- **Category / severity:** C / P2
- **Locations:** `layer2_registries_spec.md:513-515` — "At most one `security.alarm_mode` Sensor exists, and at most one `security.lock` and one `opening.open` Sensor per opening. These facts are read only by Layer-5 policies (for example `safety.posture_check`, Layer 5 §7.5)"; `layer2_registries_spec.md:606` — "Every Home Assistant **readable signal path** Heima cares about is registered exactly once, here"; `layer3_learning_spec.md:2377-2382` — "`observed_opening_state` and `observed_cover_position` resolve at the opening owner's room and must trace to a Layer-2 Sensor with one `related_opening_id` ... Opening and cover readings use stable logical Sensor identities in their fact types, for example `environment.opening_state.<sensor_id>`"
- **Owner:** Layer 2 §2.10, whose reader restriction excludes Layer 3's declared opening-evidence consumer; alternatively Layer 3 §4.8.2 if it must bind `opening.open`.
- **Defect:** One exterior window contact is needed by both `safety.posture_check` and a `thermal_exchange` learner. Registered as `opening.open`, Layer 3 may not read it ("read only by Layer-5 policies"); registered as `environment.opening_state.<sensor_id>`, it is no longer the one `opening.open` Sensor for that opening; registering both breaks "registered exactly once". No configuration satisfies all three rules.
- **Proposed direction:** Make `opening.open` the single opening-state fact readable by Layer-3 environmental slots too, or state which namespace a contact uses when both consumers exist.
- **Confidence:** medium
- **Verification:** pending

### F-X5-02 — `occupancy.physical` is "the sole" ground truth a learner may bind, but the survival model binds resolved Layer-4 occupancy

- **Category / severity:** C / P2
- **Locations:** `layer2_registries_spec.md:624-626` — "`occupancy.physical` is the sole standardized physical room-occupancy ground truth a core learner may bind; individual evidence facts are never training labels."; `layer3_learning_spec.md:983` — "`stay_duration`: anchor on the subject room's resolved occupancy transition `absent -> present`"; `layer3_learning_spec.md:988-989` — "Both profiles use only completed, resolved room-occupancy facts whose own occupancy labels are eligible physical evidence under Layer 4 §9.1"
- **Owner:** Layer 2 §3 or Layer 3 §4.4.1; the two must name one label source for physical room occupancy.
- **Defect:** `RoomOccupancySurvivalModel` anchors and targets on the `present`/`absent` transitions of the Layer-4 `occupancy` claim (filtered by provenance), not on the boolean Layer-2 `occupancy.physical`. Under Layer 2's "sole ... a core learner may bind", that binding is not allowed; under Layer 3 it is the declared input. The two labels can also differ (the Layer-4 claim is unavailable where the physical fact is, and carries a different producer fingerprint).
- **Proposed direction:** Bind the survival profiles to `occupancy.physical`, or widen Layer 2's rule to admit physically-provenanced Layer-4 occupancy.
- **Confidence:** medium
- **Verification:** pending

### F-X5-03 — Layer 3 resolves learner bindings against the active Layer-2 generation, not the candidate

- **Category / severity:** C / P2
- **Locations:** `layer3_learning_spec.md:159-161` — "At staging, Layer 3 combines blueprint and instance into one immutable `ResolvedLearningDefinition`. It resolves scope membership and only the blueprint-declared configurable bindings against the active Layer-2 generation"; `layer0_runtime_spec.md:1612-1613` — "A candidate is the active composition plus the edited definitions. Each layer validates its own part against the candidate lower layers"; `layer4_domain_spec.md:182` — "Staging resolves all bindings against the candidate Layer-2 and upstream semantic generations"; `layer2_registries_spec.md:233-236` — "per-producer **execution semantic fingerprints** become part of one composed configuration generation (Layer 0 §4.7) ... every layer swaps its active pointer together"
- **Owner:** Layer 3 §4.1.2, which departs from the composed-generation rule that Layer 0 and Layer 4 follow.
- **Defect:** One change set adds a Sensor and a learner instance bound to it. Resolving against the active Layer-2 generation rejects the binding (the Sensor does not exist yet); conversely, a change set removing a Sensor would validate the learner against a producer that the committed generation no longer has.
- **Proposed direction:** Replace "active" with "candidate" Layer-2 generation in Layer 3 §4.1.2.
- **Confidence:** high
- **Verification:** pending
