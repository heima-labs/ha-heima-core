### F-O1-01 — Overview says Layer 6 produces seven event fact types; Layer 6 registers eight

- **Category / severity:** D / P3
- **Locations:** `docs/specs/v3/architecture_overview_defined_layers.md:68` — "The seven Layer-6 event facts with their outbox records"; `docs/specs/v3/architecture_overview_defined_layers.md:490` — "Sole producer of the seven Layer-6 event fact types, each committed with its outbox record (Layer 0 §4.5)"; `docs/specs/v3/layer6_notification_spec.md:84` — "notification_kind: str                 # equals the event fact_type and the Layer-0 claim"; `docs/specs/v3/layer6_notification_spec.md:107` — "| `system.health` | `RuntimeHealthOccurrence` (Layer 0 §10.1) | administrators | attention | error | `error_opened`, `restored` ..."
- **Owner:** the overview (§3 table and §9 table); its own §11 already says "A closed registry of eight kinds" (line 555). The missing Layer-0 claim for `system.health` is the separate F-L0-03 / F-L6-05.
- **Defect:** Layer 6 §4.2 registers eight kinds, each equal to its event `fact_type`, so `system.health` is an eighth Layer-6 event fact. The overview's responsibility map and communication table count seven; the §9 row "5/0 -> 6" also lists only recovery-confirmation occurrences from Layer 0, omitting `RuntimeHealthOccurrence`.
- **Proposed direction:** count eight Layer-6 event fact types and add Layer 0's runtime-health occurrence to the "5/0 -> 6" row.
- **Confidence:** high
- **Verification:** pending

### F-O1-07 — "Global storage ceilings are hard", but the 512 MiB limit is a non-blocking watermark

- **Category / severity:** D / P3
- **Locations:** `docs/specs/v3/architecture_overview_defined_layers.md:513` — "retention floors are declared; count and global storage ceilings are hard"; `docs/specs/v3/layer0_runtime_spec.md:1109` — "It is a watermark, not an admission quota: it never rejects an observation, blocks a cycle, or removes a latest state record. If protected latest state records alone exceed 512 MiB, Persistence raises `storage_pressure` and continues to preserve them"
- **Owner:** the overview §10; Layer 0 §4.3 is authoritative, and the overview's own line 90 calls it "a 512 MiB global watermark".
- **Defect:** when protected latest state records exceed 512 MiB, Layer 0 lets the store grow past the limit and only raises `storage_pressure`; a "hard" global ceiling would require rejecting or evicting them.
- **Proposed direction:** call the global limit a pruning watermark and keep "hard" for the per-type count ceiling.
- **Confidence:** high
- **Verification:** pending
