## Findings

### F-O2-01 — Recap lists seven Layer-6 kinds; Layer 6 §4.2 registers eight

- **Category / severity:** D / P3
- **Locations:** `docs/v3_architecture_recap.md:662` — "One pipeline handles every outbound notification — the seven closed kinds of Layer 6 §4.2: Reaction follow-ups, automation availability, advisories, protective-action notices, recovery confirmations, consent requests and proposal reviews"; `docs/v3_architecture_recap.md:673` — "Three further typed occurrences complete the inputs"; `docs/specs/v3/layer6_notification_spec.md:107` — "| `system.health` | `RuntimeHealthOccurrence` (Layer 0 §10.1) | administrators | attention | error | `error_opened`, `restored` ..."
- **Owner:** the recap (orientation only); Layer 6 §4.2 is the authoritative kind table.
- **Defect:** the recap's closed enumeration and its "complete the inputs" statement omit the
  administrator `system.health` kind, so a reader of the recap concludes runtime-health errors
  are not delivered through the Layer-6 pipeline.
- **Proposed direction:** state eight kinds and add `system.health` (administrators, `attention`) to the recap's list of inputs.
- **Confidence:** high
- **Verification:** pending

### F-O2-04 — Recap provenance summary names a "resident response" kind and an extension-related `ApplyStepSource`

- **Category / severity:** D / P3
- **Locations:** `docs/v3_architecture_recap.md:157-158` — "every `HouseFact` and every `ApplyStep` carries a `kind` (sensor, analyzer, extension, reaction, admin command, resident response, timeout, recovery, system...)"; `docs/v3_architecture_recap.md:163-164` — "An extension-related `ApplyStepSource` is provenance only; it never grants an extension a direct command capability."; `docs/specs/v3/layer0_runtime_spec.md:1747-1749` — "kind: ApplyStepSourceKind # a distinct closed action vocabulary; an action is never kind=\"sensor\"/\"analyzer\"/\"extension\"/ \"semantic_resolver\""; `docs/specs/v3/layer0_runtime_spec.md:1863-1865` — "Its kind is always `kind=\"user_response\"` ... an administrator answering a request is still a response, with `ha_admin=True`"
- **Owner:** the recap; Layer 0 §5/§5.1 owns both kind vocabularies.
- **Defect:** Layer 0 closes `ApplyStepSourceKind` without `extension`, so no `ApplyStepSource` can
  be extension-related, and the response kind is `user_response`, which also covers a guest or a
  non-resident administrator answering a request; the recap describes one shared kind list for
  facts and steps that includes `extension` and a resident-only response kind.
- **Proposed direction:** list the fact-only and the shared kinds separately, use `user_response`, and replace the extension sentence with "an action never has `kind=\"extension\"`".
- **Confidence:** medium (the extension sentence may mean an action whose correlation chain includes an extension fact, but that is not what it says)
- **Verification:** pending
