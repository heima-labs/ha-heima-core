## Findings

### F-L4-01 — Activity profiles told to bind event/episode slots that `ActivityEvidenceSlot` rejects

- **Category / severity:** C / P2
- **Locations:** `docs/specs/v3/layer4_domain_spec.md:488` — "A profile that needs to know that
  something changed recently binds an event or episode slot, never the age of a state.";
  `docs/specs/v3/layer4_domain_spec.md:465` — "source: FactRef                # current typed
  Layer-2 or upstream semantic state"; `docs/specs/v3/layer4_domain_spec.md:475` — "slots:
  tuple[ActivityEvidenceSlot, ...]  # exact typed/scope-compatible bindings";
  `docs/specs/v3/layer4_domain_spec.md:626` — "`ActivityEvidenceSlot` rejects an event or
  previous-cycle source"
- **Owner:** Layer 4 §9.4 — the prose and the acceptance criterion of the same contract disagree.
- **Defect:** `ActivityProfile` has no slot type other than `ActivityEvidenceSlot` (plus one signal
  type). A profile that follows §9.4 and binds an event or episode slot is rejected at staging by the
  §10 criterion and by the slot's own `source` comment; there is no legal way to express "changed
  recently" in an activity profile.
- **Proposed direction:** Either admit a bounded event/episode slot kind in `ActivityProfile`, or
  drop the "binds an event or episode slot" sentence so the profile has no such route.
- **Confidence:** high
- **Verification:** pending

### F-L4-02 — `occupied_without_residents` acceptance gives it a baseline it cannot have

- **Category / severity:** C / P3
- **Locations:** `docs/specs/v3/layer4_domain_spec.md:391` — "It reads only those two upstream
  claims of the same cycle, adds no dwell or retained state, and asks no question about who is
  inside."; `docs/specs/v3/layer4_domain_spec.md:656` — "it has no transition adapter and raises no
  notification. The first post-restart available value seeds its baseline without inventing a
  transition."
- **Owner:** Layer 4 §10 — the sentence appears misplaced from the casa adapter bullet (lines
  649–653) into the `occupied_without_residents` bullet.
- **Defect:** A resolver with no adapter and no retained state has no baseline to seed after restart;
  the criterion as written requires a test of retained state that §9.2 forbids.
- **Proposed direction:** Move the "seeds its baseline" and "Staging rejects an unregistered initial
  episode producer" sentences into the casa transition-adapter criterion.
- **Confidence:** high
- **Verification:** pending

### F-L4-03 — Evaluator lookup key omits the per-profile activity evaluator and version

- **Category / severity:** C / P2
- **Locations:** `docs/specs/v3/layer4_domain_spec.md:84` — "the active in-memory generation
  resolves the pure evaluator by `(resolver_kind_id, implementation_version)`.";
  `docs/specs/v3/layer4_domain_spec.md:472` — "implementation_version: int" and
  `docs/specs/v3/layer4_domain_spec.md:477` — "evaluate: PureActivityEvaluator           # core
  code, resolved at bootstrap; never serialized" (inside `ActivityProfile`);
  `docs/specs/v3/layer4_domain_spec.md:324` — "A changed kind/version, output claim, scope
  membership, input binding, signal contract, semantic parameter, priority rule, or availability
  contract creates an impacted generation."
- **Owner:** Layer 4 §4.1 — the lookup and impact rules should name the profile key.
- **Defect:** For the `activity` kind, the evaluator actually used is selected by
  `claim_parameters.activity_id` and carries its own `implementation_version`; the §4.1 key
  `(resolver_kind_id, implementation_version)` cannot select it, and a profile version change with an
  unchanged kind version is not listed in §8 as an impacting change (it would only be caught as a
  "claim" or "priority rule" change by interpretation).
- **Proposed direction:** State that activity evaluators resolve by `(resolver_kind_id,
  implementation_version, activity_id, profile implementation_version)` and that a profile version
  change impacts the generation.
- **Confidence:** medium
- **Verification:** pending

## Observations

- §9.4 line 454–455 lists `occupancy` twice: "supersede `occupancy` or `presence`, `occupancy`,
  `relax`, `sleeping`, `working`" (wording).
- §5.1 line 199 allows "one declared optional signal slot", while §4.1 line 130–131 describes
  "optional authorized-signal slots" (plural); the cardinality is not stated in one place.
- §10 line 632 requires "one materialized unique output claim" per resolver, while §4.1 line 145 has
  an attached `StateTransitionEpisodeAdapter` materialize further event `FactTypeClaim`s for the same
  state resolver; whether those count as the resolver's output claims is unstated.

  profile "accepts only" the signal plus same-room occupancy and "Layer 4 performs only the finite
  snapshot/contract checks"; it is unstated whether Layer 4 binds `calendar.work_location` as a slot
  or relies on the Layer-3 contract not emitting the signal.
