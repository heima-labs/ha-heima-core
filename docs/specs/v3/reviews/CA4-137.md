**Status:** specification reviewed (2026-10-21).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

- **Responsiveness.** No change touches the hot path; every adjustment is slow-path or staging-time.

## Decisions (developer-approved 2026-10-21)

1. No calendar input for extensions; classified windows as a possible evolution with third parties.
2. Event slots only with `history`, never a trigger.
3. Restart expiry re-armed from the restart instant.
4. `max_result_age` floor includes the run deadline; the guarantee covers only the forced window.
5. Mechanical corrections as listed in the backlog entry.

## Scenario review

| Scenario | Result |
|---|---|
| Extension blueprint asks for calendar input | No field exists; core calendar features unaffected. |
| Event slot on door openings, 24 h history, 15 min cadence | Occurrences in the window at each run; no run per event. |
| Event slot without history | Rejected at registration. |
| Stable value for 6 h, then restart | Fact stays available; expiry re-armed from restart; first runs refresh it. |
| Extension already failing at shutdown | Value lives at most `max_result_age` after restart, then expires. |
| 15 min cadence, 2 min run deadline | `max_result_age` must be at least 22 min; a forced window alone never expires it. |
| Room rename | Extension fact fingerprints unchanged. |
| History slot of 30 days on an unbound fact type | Retention requirement registered; coverage reported while warming up. |
| `M_slow` 64 MiB, envelope 128 MiB | Runs rejected, `extension_envelope_exceeds_capacity`, warning in Layer 8. |
| Remove an instance feeding a Fusion | Rejected unless the Fusion is edited in the same change set. |
| New instance with an unproduced input | Staging error and `extension_requirement` suggestion from the change set. |
| Extension producer with an event claim | Admitted by Layer 0 §4 as a Layer-2-generation claim. |
