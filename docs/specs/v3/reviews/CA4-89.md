# CA4-89 — per-Reaction decision state and one outcome vocabulary

**Status:** specification reviewed (2026-10-14).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved, S4 of the CA6 reread)

1. The decision record is a per-Reaction state fact `reaction.decision.<digest>` (digest over
   `[reaction_id]`, reserved pattern `reaction.decision.*`, owner `layer5.reaction_decision`). Its
   value holds no per-cycle identity, so Layer 0's ordinary write-on-change persists only changes.
   This supersedes the event shape of CA4-79.
2. `ReactionEvaluationOutcome` is the one vocabulary for one-shot and step-programmed Reactions and
   gains `normal_exit`. `evaluate_program` returns it directly, restricted to `not_triggered`,
   `eligible` (active, zero or more selected steps), `normal_exit` and `abstained`; Layer 5 adds
   `guards_unsatisfied`.

## Why

Every enabled Reaction is evaluated against every snapshot (Layer 5 §6.0), so the event shape
wrote one fact per cycle for a long abstention or a running program, and its retry rule had no
Layer-0 deduplication. The program vocabulary duplicated three outcome values under other names,
lacked guard failure, and was never mapped to the recorded outcome.

## Alternatives rejected

- Event with in-memory change suppression: a hand-written write-on-change, plus a closing record.
- Recording only fired triggers: loses the most common "why not" (abstention on missing input).
- Keeping two vocabularies with a mapping: two names for one concept.
- New lifecycle names (`idle`/`active`/`ended`): large ripple over `eligible`, and `active`
  collides with the activity claim value.

## Overlap check

Reuses the state write-on-change, latest-value index, latest-record retention exemption and as-of
reconstruction of Layer 0 §4.0–4.3, and the per-channel digest pattern of
`actuator.channel_state.<digest>`. One new outcome value (`normal_exit`) replaces the program's
private vocabulary; no new type. Removal of a Reaction's decision claim follows the Reaction
removal lifecycle (CA6 S5, open).

## Cost

A typical firing writes two values (to `eligible`, back to `not_triggered`); an abstention lasting
a day writes one. The CA4-79 estimate of 300–2,000 firings a day gives at most about 4,000 writes a
day; the 50,000-record ceiling applies per Reaction, because the fact type is per Reaction. In the
cycle each Reaction submits one candidate compared in O(1), like any state producer.

## Scenario review

| Scenario | Result |
|---|---|
| Trigger fires, wind guard blocks | State changes to `eligible`/`blocked`/`("wind",)`; next cycle back to `not_triggered`. |
| Required input unavailable for a day | One `abstained` value. |
| Retried evaluation of the same snapshot | Unchanged value; nothing written. |
| Reaction in `notification_only` fires | `admission="not_reached"`, `execution_mode` trial. |
| Program active, waiting for its next timed step | One `eligible` value with `admission="not_reached"` for the whole wait. |
| Program step vetoed by a guard | `guards_unsatisfied` with the capability ids. |
| Verified end of a program activation | `normal_exit`, admission of its terminal step or `not_reached`. |
| "Why did the awning not lower at 15:00?" | As-of reconstruction of the decision state at 15:00. |
| Superseded values older than 14 days | Pruned; the latest value remains. |
