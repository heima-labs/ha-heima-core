# CA4-83 — Room registry

**Status:** specification reviewed (2026-10-13).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision

Layer 2 §2.6 defines `Room(room_id, ha_area_id, display_name, floor, enclosure)`, staged with the
registry generation.

## Overlap check

`Zone` groups rooms; `Location(room=...)` references `room_id`; `Topology` derives
`floor_by_room` and `enclosure_by_room` from it. HA areas are linked, not duplicated: the name may
come live from the area; semantic attributes never do.

## Scenario review

| Scenario | Result |
|---|---|
| Area renamed in HA | Room shows the new name; no fingerprint change, no impact. |
| Area moved to another HA floor | No change in Heima until `floor` is edited and committed. |
| Room without area and without name | Rejected. |
| Two rooms linked to one area | Rejected. |
| Room removed | Impact record lists Sensors, Actuators, openings, zones, resolvers, Reactions. |

Textual review only; no V3 runtime test has run.
