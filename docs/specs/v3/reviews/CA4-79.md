# CA4-79 — durable decision record for fired evaluations

**Status:** specification reviewed (2026-10-13).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision

Layer 5 appends one `reaction.decision` event fact per evaluation whose outcome is not
`not_triggered`, with outcome, reasons, failed guard binding ids, execution mode and admission
result. Not-triggered evaluations write nothing.

## Alternatives rejected

- Write-on-change state of every evaluation: about two writes per trigger firing and no added
  information, since "nothing fired" is already in the trigger fact's history.
- Live status only: no answer for a past non-action.

## Cost and performance

About one write per trigger firing: 300/day for a typical home (20 Reactions x 15 firings), 2,000/day
for an intensive one (40 x 50); ~0.5-0.6 KB each, so 2.5-15 MB and 4,200-28,000 records over the
default 14-day retention, under the 50,000 per-type ceiling and ~3% of the 512 MiB watermark. In the
cycle it is one O(1) in-memory append in cycles where a trigger fires; durable writes join the
asynchronous batch queue. Layer 1 adds no type, only the approved event fact.

## Overlap check

`automation.availability` records only resident-notified blocks; `ReactionExecutionAudit` records
execution events after admission; `actuator.target_lifecycle` records admitted targets. None holds
the evaluation outcome and failed guards of a fired trigger.

## Scenario review

| Scenario | Result |
|---|---|
| Trigger fires, wind guard blocks | One fact: `eligible`, `blocked`, `action_guard_active`, wind guard id. |
| Trigger fires, semantic guard fails | One fact: `guards_unsatisfied` with that guard id. |
| Trigger never fires all afternoon | No fact; explanation from the trigger fact's history. |
| Reaction in trial mode fires | One fact with `admission="not_reached"`. |
| Evaluation retried | No second fact (evaluation identity). |
