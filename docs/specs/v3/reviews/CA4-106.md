# CA4-106 — panel addresses and notification links

**Status:** specification reviewed (2026-10-15).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decision.** Layer 6 §7.2: `data.url` "pointing to the Layer-8 panel" for the proposal
  digest only; §7.3: a fallback actionable phase stays answerable from the Layer-8 surface.
  Layer 8 §4: authorization in the backend; §5: sections.
- **Gap.** No address scheme; no link for requests, Reaction notices or the fallback.
- **Overlap check.** Reuses existing stable ids (`request_id`, `reaction_id`, `proposal_id`,
  registry ids, item tag, `composed_generation_id`) and §8 explanations. No new identity.
- **Dependency direction.** Layer 6 depends on the address format as a public contract; it never
  calls Layer 8.
- **Owner/dependents.** Layer 8 §5.1, §16; Layer 6 §4.2, §7.2, §7.3, §14.

## Decisions (developer-approved)

1. Scheme `/heima/<section>[/<type>[/<id>]][?at=<EvidenceInstant>]`, closed English tokens.
2. Ids only; no names, no `entity_id`; a `request_id` in an address grants nothing.
3. Missing and forbidden objects give the same notice.
4. Per-kind links in Layer 6, including the fallback message.

## Scenario review

| Scenario | Result |
|---|---|
| Recovery request on a phone without action support | Link opens the request in To do; answer via ingress. |
| Fallback `persistent_notification` | Message ends with the Markdown link. |
| Awning action notice at 15:00 | Link opens the Reaction's "Why?" at 15:00. |
| Reaction removed later | Same link opens Automations with "no longer available". |
| Resident opens an admin-only sensor address | Same notice as a missing object. |
| Room renamed | Address unchanged and still valid. |
| Administrator opens a `todo/request` address | Overview with that request selected. |

Textual review only; no V3 runtime test has run.
