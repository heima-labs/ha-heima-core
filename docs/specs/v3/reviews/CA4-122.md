# CA4-122 — occupied without residents and absence programs

**Status:** specification reviewed (2026-10-19).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Approved people model §5.1, §5.4, Q6, Q7, Q12 (dissolved), Q13; CA4-120
  casa claims and occupancy guard; CA4-121 `household.planned_absence` and its 14-day horizon;
  Layer 5 `planned_absence_program` (`not_ended` suppression, normal exit), descriptor contract and
  diagnostic registry; Layer 3 `ThermalResponseParameter`.
- **Gap.** No construct expressed "someone inside, no resident home"; absence programs could not
  pause and resume for a sitter or cleaner; the comfort trajectory had no minimum absence duration.
- **Overlap check.** The claim combines two existing claims, which Layer 4 already permits; `pause`
  reuses the existing `not_ended` suppression; the minimum is a pure function of the existing
  `ThermalResponseParameter` fields. New: one claim, one descriptor field, three evaluation reasons.
- **Owners.** Layer 4 §9, §9.2, §10; Layer 5 §3.2 descriptor contract and table, `planned_absence_program`
  rule 9, §4.0 registry, §7 comfort-trajectory paragraph, §8; overview; recap.
- **Deferred.** Behavior-learning censoring from the same claim (CA4-123).

## Decisions (developer-approved 2026-10-19)

1. Layer 4 claim `occupied_without_residents@casa`: `True` iff occupancy `present` and presence `away`;
   unavailable if either input is; no warning.
2. Descriptor field `when_occupied_without_residents: continue | pause`, fixed per version: `pause`
   for comfort trajectory and presence simulation, `continue` for the other five.
3. `pause` = `not_ended`; resume on the next evaluation after the claim turns `False`, requested by
   `occupancy.departure` and `presence.return`; only a household return ends an absence program.
4. Comfort-trajectory minimum absence = clamp(drift time for `thermal_delta_min_c` at the slowest
   drift + conservative recovery, 24 h, 7 days); default 48 h; `recovery_beyond_horizon` beyond 7 days
   of recovery; the 14-day horizon exceeds the 7-day ceiling.
5. New evaluation reasons `occupied_without_residents_pause`, `absence_below_minimum`,
   `recovery_beyond_horizon`.

## Scenario review

| Scenario | Result |
|---|---|
| 10-day absence, sitter inside 1 h per day | Trajectory and simulation paused during the visit, resumed after; no exit. |
| Same, claim unavailable (tracker outage) | `not_ended`; nothing sent; no exit. |
| 30-hour absence | Simulation runs; trajectory `absence_below_minimum`. |
| High-inertia house, derived minimum 80 h, 3-day absence | `absence_below_minimum`. |
| 3-week absence, end beyond horizon | Passes the minimum. |
| Parameter with 8-day conservative recovery | `recovery_beyond_horizon`. |
| Untracked resident alone during a declared absence | Claim `True`; trajectory paused (harmless). |
| Guest alone, routine "projector on → dim lights" | `continue`; routine acts. |
| Sitter leaves, last resident returns later | Program resumes at `occupancy.departure`; ends at `presence.return`. |
