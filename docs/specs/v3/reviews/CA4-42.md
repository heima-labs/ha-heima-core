# CA4-42 — descriptor consent and authority review

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision and impact

The developer selected a descriptor-owned consent declaration and required
resident consent for all three Initial-V3 environmental descriptors. The two
programmed descriptors already required it. The developer subsequently
required it for `routine.actuation_bundle` as well. Layer 5 §3.2/§4.2 now records the
boolean on each frozen descriptor version and validates the matching authority
transition shape. Layer 3 §6.3.1 and Layer 5 admission agree that consent is
authority, not a diagnostic action guard or missing-evidence condition.

| ID | Scenario | Required result |
|---|---|---|
| S1 | Any of the six Initial-V3 descriptors is promoted without current consent | `authorized_awaiting_household_consent`; no command or availability occurrence |
| S2 | Authorized resident grants consent for the exact generation | Fresh evaluation may become `automatic`; no missed step replay |
| S3 | Consent is revoked during a multi-call step | Per-call fence stops unsent calls; no compensation of sent calls |
| S4 | Admin disables or replaces a generation | No future command; successor inherits no consent |
| S5 | Future descriptor declares no consent requirement | Consent field must be `None`; admin authorization alone can enable action |
| S6 | An actual safety guard fails while authority is valid | Ordinary `action_guard_active` availability path applies |

**Review result:** all six Initial-V3 registrations, transition shape,
runtime gate and suppression taxonomy use one rule. This is a specification
review only.
