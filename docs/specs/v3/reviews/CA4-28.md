# CA4-28 — deep immutability, depth counting and invalid evidence

**Status:** specification reviewed (2026-10-10).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decisions and exact gap

The developer approved freezing `value`, `evidence` and retained `PersistedProjection`s once at
construction (28a/A), one explicit collection-depth rule (28b), and fail-soft handling of a
non-finite number in `evidence` (28c/A). Layer 1 had a frozen dataclass whose nested maps stayed
mutable; depth was described differently for dataclass values, evidence and projections; and
§4.3 (evidence violations become `{}`) contradicted the §10 acceptance criterion (NaN in evidence
rejects the fact). The original concern about hold-checkpoint depth no longer applies: CA4-01
removed the hold checkpoint, and every remaining checkpoint entry is an ordinary
`PersistedProjection`.

## Reuse and owners

Layer 1 §3 owns the freeze and the depth rule, reusing the validation pass that already measures
depth and canonical size; §4.3 owns evidence failure handling; §10 acceptance is aligned. Layer 0
§4.1 and §6.4 rely on immutability instead of per-reader copies. The canonical JSON wire form is
unchanged. No new type or storage path.

## Scenario review

| Scenario | Required result |
|---|---|
| Consumer mutates a nested evidence map or list | Mutation fails; buffer, index, snapshot and other readers see the original. |
| Hold audit read by two consumers | Both share one immutable value; no reconstructed copy needed. |
| Value with a third nested collection | Fact rejected. |
| Evidence with a third nested collection or a NaN | Fact created with `evidence={}` and a diagnostic. |
| NaN in `value` | Fact rejected. |
| Frozen sequence serialized | Same canonical JSON array bytes as before freezing. |

This is document-level evidence; no V3 runtime test has run.
