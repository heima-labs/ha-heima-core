# CA4-101 — weekly occurrence identity

**Status:** specification reviewed (2026-10-15).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Approved rules.** First-fold execution and single start per civil request; timezone change
  re-arms without replay; `(owner, job_id)` replacement; restart keeps only standing definitions;
  CA4-99/100 references and deadline construction.
- **Gap.** "No replay" had no occurrence identity: Monday 07:00 `Europe/Rome` served at 05:00 UTC,
  zone changed to UTC at 05:01 UTC, and Monday 07:00 UTC became a future due.
- **Consumer audit.** No Initial-V3 `CronEntry` uses `WeeklyRecurrence`: Heima-owned recurrences
  are `IntervalRecurrence` (checkpoint, continuity), admin schedules are HA `schedule.*` helpers
  (Layer 0 §3.1). The only use is `security.presence_simulation`'s session (Layer 5 §7.2), a
  descriptor time window inside an activation.

## Decision (approved)

1. Remove the weekly `CronEntry` from Initial V3: `CronEntry.pattern` is an `IntervalRecurrence`;
   `WeeklyRecurrence` stays a value type for descriptor windows and bucketing; a future weekly
   `CronEntry` needs its own reviewed identity contract.
2. Presence-simulation session identity: requested civil date; a served date never starts again
   within the activation; shifted starts keep their requested date; merged starts make one
   session; no catch-up. Memory belongs to the activation; restart restores none.

## Alternatives rejected

- A generic per-job watermark of served civil occurrences for weekly `CronEntry`s: machinery for a
  case with no consumer.
- Simplifying the session to "every day": the same-date zone-change case remains, so it does not
  remove the rule.

## Scenario review

| Scenario | Result |
|---|---|
| Monday 07:00 Rome session served; zone → UTC at 05:01 UTC | No second Monday session in that activation. |
| Session served; clock regresses before its start | Not started again. |
| `Pacific/Apia` Friday 2011-12-30 04:00 requested | Starts Saturday 00:00, identity Friday. |
| Two requested dates resolve to one start | One session serving both. |
| Delivery late past a session's end | Not started; no catch-up. |
| Delivery late within a session | Acts for its remaining time. |
| Restart during an absence | No activation restored; a new activation starts from current inputs. |
| `CronEntry` registered with a `WeeklyRecurrence` pattern | Rejected at registration. |

Textual review only; no V3 runtime test has run.
