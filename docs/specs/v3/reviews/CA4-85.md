# CA4-85 — Reaction display names in the Layer-5 catalog

**Status:** specification reviewed (2026-10-13).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision

The Layer-5 layer generation is the Reaction catalog; each entry carries `display_name` and points
to the current configuration generation. A rename is a composed commit that changes only the
catalog. Effective names are unique after trim, NFC and case-folding.

## Alternatives rejected

- Name inside the configuration generation: every rename would restart the Reaction in trial and
  cancel its jobs.
- A separate label registry with its own command: a second naming mechanism, unlike every other
  registry name.
- A configuration generation "metadata-only successor" that inherits authority: would require
  activations, jobs, holds and the dispatch fence to survive a generation-id change.

## Scenario review

| Scenario | Result |
|---|---|
| Rename an automatic Reaction | Same configuration generation; mode, consent, jobs unchanged; empty impact. |
| Rename a learner-origin Reaction | Allowed; its configuration stays proposal-only. |
| "Bathroom fan" vs "bathroom fan " | Rejected as duplicate. |
| Two unnamed solar-shading Reactions in one room | Second rejected until named. |
| Restore an old name from history | Ordinary change-set entry; no demotion. |

Textual review only; no V3 runtime test has run.
