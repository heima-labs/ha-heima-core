# CA4-57 — common Reaction guard naming review

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decision and impact

The developer approved replacing the misleading `EnvironmentalGuard*` type
family with `ReactionGuard*`. Layer 5 §3.2 remains the single owner of the
capability registry, contract, binding and profile generation. Layer 3's
candidate and proposal references use the same type. No guard evaluator,
admission rule, field shape or authority changes. Historical backlog quotations
are preserved as dated rationale. This protects V3's shared descriptor pipeline
from a separate guard mechanism per device or domain.

| ID | Scenario | Required result |
|---|---|---|
| S1 | Environmental descriptor with weather and safety inputs | Registered `ReactionGuard*` capabilities and one profile |
| S2 | Security presence simulation with `presence` | The same registry and staging path, without an environmental-only type |
| S3 | Future routine with a different typed guard | New reviewed core capability in the same registry; no parallel evaluator |

**Review result:** Layer 3 and Layer 5 use the same renamed type family, and
Layer 5 §8 checks the common path. This is a terminology and contract-ownership
correction; implementation tests remain for V3 development.
