# CA4-50 — quiet-hours action guard review

**Status:** specification reviewed on 2026-10-05.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decision and impact

The developer chose a common action guard rather than removing the unsupported
quiet-hours reference. The capability is declared by a versioned Reaction guard
contract, not applied globally to every Actuator. The developer also corrected
the identifier convention: contract/capability ids use `.v1`, with a separate
`version="1"` where the type requires it. Layer 5 §3.2 owns the capability and
pure decision; Layer 2 owns the boolean state producer. Layer 6 notification
quiet-hours routing remains distinct and is not specified by this action guard.

| ID | Scenario | Required result |
|---|---|---|
| S1 | Declaring descriptor, current `quiet_hours.active=True` | Action veto, `action_guard_active` |
| S2 | Declaring descriptor, current fact exact `False` | This guard passes; other admission gates still apply |
| S3 | Declaring descriptor, unavailable/stale/non-boolean fact | No action; `action_guard_active` |
| S4 | Descriptor without the capability | No quiet-hours action veto, regardless of the fact value |
| S5 | HA `schedule.*` changes at its own boundary | Layer-2 boolean fact changes; next frozen snapshot re-evaluates the guard |
| S6 | Notification would be deferred by Layer 6 | Its delivery decision does not change Layer-5 action admission |

**Review result:** Layer 2 §9, Layer 5 §3.2/§8, overview and recap agree on
the owner, input and scope. This does not assign `quiet_hours.v1` to an
Initial-V3 descriptor that has not declared it, and does not implement V3.
