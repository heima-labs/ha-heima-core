# CA4-14 — artifact adoption and serving identity

**Status:** specification reviewed on 2026-10-06.
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact and decision

The original Layer-3 adoption rule sent every `pinned` revision to Layer 5,
although diagnostic findings and live signals have no configured Reaction.
It also did not define how a compatible action artifact could change without
creating a new Reaction generation. A broad learner fingerprint description
could invalidate a statistical response when only its serving objective
changed. The owner contracts are Layer 3 §§4.1.2, 4.5, 4.9 and 6.1–6.3,
and Layer 5 §§3, 4.1–4.2, 6.0 and 8.

Reuse the validated immutable `ArtifactRef`, existing Layer-3 shadow and
promotion gates, `LearningProposalCandidate`, `review_proposal`, immutable
Reaction generations, and current action authority/consent. The new
`("reaction.artifact_adoption", 1)` candidate kind is core registered and
has only current Reaction/generation, declared artifact role and exact
revision. The accepted adoption proposal remains terminal; the adopted
revision lives in an append-only transition outside the semantic Reaction
fingerprint. Mode changes are authenticated transitions on that same chain,
not a Reaction restage. Diagnostic findings require no adoption. Registered
live signals use a separate Layer-3 adoption chain for their exact consumer.
An analysis `definition_fingerprint` excludes serving-only parameters; the
distinct `serving_generation_fingerprint` invalidates old operational use
without retraining.

This retains V3's one typed Reaction action path, current admission and
consent gates, and core-owned bounded learning. It does not change V2 code.

## Reviewed scenarios

| ID | Case | Required result |
| --- | --- | --- |
| A1 | Diagnostic-only model publishes a valid new artifact | Current bounded finding refreshes; no adoption mode or Layer-5 proposal. |
| A2 | One artifact supports diagnostic and signal egress | Eligible finding remains visible while signal adoption is pending. |
| A3 | Signal initial promotion | Exact eligible artifact, registered consumer and admin-selected mode commit together after required shadow. |
| A4 | Signal `pinned` revision | Admin names the exact artifact and current head in Layer 3; old revision remains selected until commit. |
| A5 | Signal `bounded_adaptive` revision | Core checks unchanged vocabulary, consumer, scope, expiry and approved bounds; failed check emits no signal from new revision. |
| A6 | Signal artifact withdrawn, stale or changed serving generation | No signal from the invalid chain; an earlier signal's own expiry is not extended. |
| A7 | Reaction initial artifact and compatible refresh | Exact selected revision commits with notification-only configuration; later bounded refresh changes only adoption, not generation or consent. |
| A8 | Two `pinned` revisions with identical Reaction parameters | Distinct artifact-adoption proposals; accepting one appends one adoption transition through `review_proposal`. |
| A9 | Incompatible Reaction revision | Changed definition, scope, guard, action or approved bounds cannot auto-adopt; ordinary configuration review applies. |
| A10 | Admin enters or leaves `bounded_adaptive` | Same artifact remains adopted; entry checks current eligibility/bounds, exit fixes the revision; Reaction authority and resident consent remain. |
| A11 | Mode switch races with refresh or crashes | Current-head compare-and-swap yields one complete winner; retry cannot create duplicate heads or silently switch mode. |
| A12 | Adopted timing artifact becomes unusable | Authorized seed replaces learned delay; pending step recalculates from its original anchor, without replaying a completed step. A non-fallback action role abstains. |
| A13 | Serving objective or practical delta changes | Response artifact and analysis revision remain; serving fingerprint and candidate semantic identity change. An approved Reaction retains its prior frozen objective. |
| A14 | Candidate kind or assessment forged | Layer 5 rejects an unregistered kind, noncurrent Reaction/role, mismatched artifact assessment or raw action payload before proposal persistence. |

Layer 3 §4.9 supplies the diagnostic/signal/policy × `pinned`/`bounded_adaptive`
matrix. Layer 5 §4.2 supplies adoption-chain ordering and current-eligibility
checks; §8 contains the action acceptance cases. The overview and recap
point to these owner contracts. CA4-13 remains open for the distinct learned
delay publication, model eligibility and trigger-job details. No executable
V3 test was run, so this status is specification readiness only.
