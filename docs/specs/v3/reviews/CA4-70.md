# CA4-70 — irreducible retry-queue overflow and progressive recovery

**Status:** specification reviewed (2026-10-13; progressive recovery correction).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record before normative edit

The developer approved the exceptional global gap on 2026-10-12 and progressive recovery on
2026-10-13. CA4-38's finite budget, nonblocking admission and ordinary per-stream loss order
remain approved. The original contradiction was that distinct latest state items or continuity
boundaries can alone exceed the finite budget. The initial CA4-70 recovery then required all
state claims in one atomic re-seed, which could exceed that same budget and could not recreate
lifecycle proof from an HA snapshot. The approved correction permits the global gap to close
before all keys recover, with each durable state key remaining unknown until a valid new
producer assertion is durably acknowledged. Generic reuse of an older state as current was
considered and not selected; the existing separate desired-target Recovery checkpoint is
unaffected.

Reuse Layer 0's `queue_overflow` reason, continuity timeline, watermark, state index,
`AppendOrder`, HA intake barrier and atomic per-cycle batches. Layer 0 §§4.0/4.2/4.4/4.6 own the
mechanism; §5.1.1.2 and Layer 5 §3.2 consume managed-episode proof; Layer 3 §§4.2/4.4.2 consume
coverage. Layer 0 §4.8 and Layer 6 are live in-memory observers, not durable acknowledgement
observers. The correction must not manufacture state changes, notifications, physical edges,
resident corrections or holds. No V2 migration or second writer/queue is introduced. Relevant
counterexamples are many distinct temperature sensors, unavailable channels, unchanged
states, and lifecycle claims such as `reaction.managed_episode`.

## Scenario review

| Scenario | Expected contract result |
|---|---|
| Ordinary overflow fits after stages 1–2 | Per-stream gap; latest queued states and boundaries retained; unrelated streams remain complete. |
| Protected latest states/boundaries alone exceed budget | Global gap and baseline invalidation; oldest items may be dropped; queue remains within budget. |
| Total re-seed exceeds queue budget | Schedule fresh assertions over successive cycles using available capacity; no full snapshot queue and no extra blocking write. |
| Unchanged producer assertion | One durable baseline record when admitted, with its actual validation-cycle instant; no duplicate live-buffer transition or §4.8 notification. |
| New state change while a seed is pending | Preserve `AppendOrder`; an older acknowledgement cannot overwrite the newer durable baseline. |
| Seed is discarded or its write fails | Key remains unrecovered; later fresh assertion can retry; no recovery claim from queue admission alone. |
| Another irreducible state/boundary loss during recovery | Advance global baseline invalidation; earlier seeds do not validate the new baseline generation. |
| HA state available without a report-age gate | Apply the binding's existing state semantics; a new device measurement is not required. |
| HA state unknown/unavailable, or report-age gate fails | Producer asserts `available=False`; valid acknowledgement restores the baseline but not stream availability. |
| Global closure with keys still unrecovered | Close at the acknowledged HA intake/accounting boundary; only reads requiring those keys remain incomplete with `queue_overflow`. |
| History before a delayed seed | Do not backdate the seed or use it to reconstruct the preceding unknown interval; retention and observation coverage remain distinct. |
| Lifecycle claim lacks proof | Stay durably unknown; an HA active reading cannot recreate a managed opening or grant resumption. |
| Crash before opening or during recovery | Unadvanced watermark/process gap or open durable global gap prevents optimistic completeness; do not accept invalidated managed proof. |
| Crash after closure with keys still unrecovered | Persisted invalidation and per-key seed acknowledgements survive; closing the gap does not revive old records. |
| Live automation, quiet-hours subscription, hold-audit event | Live current state/observers/holds follow their existing contracts; durable seed adds no false change; lost audit is incomplete. |
| Lower budget | Applies at next overflow check; no retroactive discard merely on health publication. |
