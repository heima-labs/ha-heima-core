# CA4-70 — irreducible retry-queue overflow

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record before normative edit

The developer approved the exceptional global gap on 2026-10-12 after reviewing comparable bounded-queue systems. CA4-38's finite budget, nonblocking admission and ordinary per-stream loss order remain approved. The exact contradiction was that arbitrarily many distinct latest state items or continuity boundaries can alone exceed a finite budget, although §4.6 protected all of them. Reuse Layer 0's `queue_overflow` reason, process-wide continuity timeline, watermark, current-state index, HA intake barrier and atomic durable batch. Layer 0 §§4.4/4.6 own the rule; Layer 3 §4.4.2 consumes coverage. The overview, recap, failure/diagnostic text and acceptance cases depend on it. V3 starts without V2 migration, must keep one generic rule for every state/event producer and must not block HA admission or commands. Counterexamples include many unique temperature sensors, many actuator channel states, and audit-event/boundary volume; retaining the latest state of only one flapping sensor is insufficient to prove the budget.

## Scenario review

| Scenario | Expected contract result |
|---|---|
| Ordinary flapping state or event overflow fits after stages 1–2 | Per-stream gap; latest queued state and boundaries retained; unrelated streams remain complete. |
| Distinct latest states alone exceed budget | Enter one global epoch, discard oldest retained items as required; neither budget nor admission blocks. |
| Boundary metadata alone exceeds budget, or one item exceeds budget | Coalesce loss into the fixed-size global marker, including its earliest start; oversized item is discarded. |
| Repeated overflow during outage | One open global epoch extends; no per-stream metadata or diagnostic list grows without bound in the queue. |
| Read intersects global epoch, including an otherwise unaffected stream | `queue_overflow` incomplete; no zero-count or at-or-before state carry across the gap. Layer 3 censors the sample. |
| Storage resumes before a fresh full HA intake | Durable gap may open, but it does not close and old durable latest values do not become current. |
| Fresh HA intake includes unavailable individual channels | Closure may proceed only after all staged current-state claims are explicitly re-seeded, including unavailable claims, in the closure transaction. |
| Crash before gap acknowledgement or during reseed | Unadvanced watermark/process interruption or still-open durable gap prevents optimistic completeness. |
| Closure transaction succeeds | Complete re-seed and end boundary are atomic; reads after the end can regain coverage according to each stream's ordinary availability. |
| Budget lowered by a health snapshot | No retroactive discard; next overflow check can enter global fallback. |
| Hold-audit event discarded | Live hold unaffected; historical audit coverage incomplete. |

This is document-level scenario evidence only. No V3 runtime, crash or performance test ran.
