## Impact record

  invariants 1–2, D1); Layer 2 §2.6 `Room` pattern (semantic attributes stored, name live from HA)

- **Gap.** No person classification existed. "Non-administrator" meant "resident" at the Layer-0
  ingress, a recipient link made a Layer-8 resident, and consent authority accepted any HA user, so a

  request was recorded as `admin_command`, mixing path and actor.
- **Overlap check.** `Person` is not a parallel directory: identity, name and trackers stay in HA,
  Heima stores only role and user link, as `Room` stores only floor and enclosure. The recipient's
  `ha_user_id` and `audiences` move to the Person (derived `residents`), leaving only
  `administrator`. `UserActor` replaces the two actor categories; `user_response` replaces
  `resident_response` and names the path only, as D6 will do for manual control.
- **Owners.** Layer 2 §2.5, §2.7, §2.8, §9; Layer 0 §5, §5.1, §5.1.1 (condition 3 and provenance
  only), §5.1.3, §7.4 baseline kind, §7.4.1, §13; Layer 5 §6.0 consent and advisory owners, §6.1
  baseline kind, §4.2 command 7, §7.1.1, §8; Layer 6 §5.1, §5.2, §5.4, §14; Layer 8 §4, §5, §5.1,
  §6.1, §13, §16; architecture overview.
- **Superseded rule.** CA4-86's actor-category mapping (`ha_admin` response as `admin_command`,
  `resident` for every non-administrator) is replaced by `UserActor` and `user_response`; CA4-86's
  record stays as history.
- **Deferred to later slices.** Manual-control event and hold origins (CA4-119); occupancy and
  household presence from resident persons (CA4-120); `house` audience, public text and visibility

## Decisions (developer-approved 2026-10-19)

1. Layer 2 `Person(ha_person_id, household_role, ha_user_id)`; unclassified HA persons and users
   with no Person count for nothing; drift in HA raises a diagnostic and never changes authority.
2. Actor has two independent axes, `UserActor(household_role, ha_admin)`; a non-resident
   administrator (B2B) configures but makes no household decision.
3. Owners admit: recovery confirmation `resident` and `admin`, the latter for a non-resident only
   as a last resort; household consent and advisory feedback `resident` only.
4. Consent authority references resident Persons with an HA user; reclassification or removal
   needs dispositions in the same change set.
5. Recipients reference a Person; `residents` derives from it; a recipient without a Person must be
   an administrator.
6. Layer-8 roles derive from the two axes; new admin section People.

**Value set in this pass (to confirm):** the last-resort escalation window is 2 hours. "No resident
reachable" is read from the active Layer-6 generation (no resident recipient with an endpoint), not
from runtime delivery outcomes, so Layer 0 takes no feedback dependency on Layer 6 delivery.

## Scenario review

| Scenario | Result |
|---|---|
| Guest with an HA account answers a recovery confirmation | Rejected at the ingress (`guest`, not admin). |
| Tablet user (no Person) answers advisory feedback | Rejected at the ingress. |
| Installer administrator (no Person) approves a recovery request after 10 minutes, resident recipient exists | Rejected by the owner with `awaiting_resident_answer`; request stays open. |
| Same approval after 2 hours | Accepted; `ApplyStep` `kind="user_response"`, `UserActor(none, true)`. |
| Installer approval, no resident recipient with an endpoint | Accepted immediately. |
| Resident who is also HA administrator gives advisory feedback | Accepted as resident. |
| Resident not in consent authority answers `grant` | Rejected by the owner. |
| Authority member reclassified to `guest` without dispositions | Whole change set rejected. |
| Same with `revoke_current_consent` | Consents revoked, future jobs cancelled. |
| HA relinks a resident's person to another user | Diagnostic; stored link and authority unchanged until commit. |
| Recipient without Person and without `administrator` | Rejected at staging. |
| Resident reclassified to `guest` | Leaves `residents` at the next delivery; no recipient edit. |
| Guest edits notification preferences | Rejected. |
| Client sends a forged `UserActor` | Ignored; re-derived at the boundary. |
| Wall switch through an approved physical adapter | `user_response` provenance with `actor_type="physical"`, no `UserActor`. |
