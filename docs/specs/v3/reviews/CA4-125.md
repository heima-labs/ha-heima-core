**Status:** specification reviewed (2026-10-19).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Approved people model §6, §7, invariants 5 and 7, D1, D4, D5; CA4-118 roles;
  CA4-120 header rule; CA4-121 guest stay; CA4-113 map card and `control_rooms`; Layer 8 §4, §5.2,

- **Overlap check.** Registers extend the existing administrator/resident rendering split. The

- **Owners.** Layer 1 §3 terminology note; Layer 8 §4.1, §5.2, §7, §9.8.1, §9.10, §9.11, §9.14,

## Decisions (developer-approved 2026-10-19)

1. Three text registers chosen by the backend: administrator, resident, public (guests, devices,
   no-role users, map card): no identity, no resident presence or times, no security posture; a
   security-related reason shows as "automation active".
2. A non-resident administrator sees configuration, diagnostics and health, not household presence,
   resident notification text (kind, audience and phase only) or residents' names.
3. History: names only for resident viewers (own actions) and administrators who are residents;
   roles otherwise; no history for guests and devices.
4. Control scope: card `control_rooms`, then administrator-set `UserControlScope`, then the active
   stay's guest rooms for guest and device users, then every room; never a security boundary.
5. "Resident" names only the household role; reader-facing wording becomes "user-facing" and
   "user-visible"; Layer-6 `resident_visible` becomes `user_visible`.

## Scenario review

| Scenario | Result |
|---|---|
| Guest taps an automation badge | Public reason, no names or resident times. |
| Presence simulation seen from the tablet | "Automation active", no reason. |
| Installer opens notification history | Kind, audience, phase; no text, no names. |
| Installer opens the Overview | No household presence in the header. |
| Administrator who is a resident opens history | Names shown. |
| Stay active in room 2, tablet without `control_rooms` | Controls only room 2. |
| Stay ends | Tablet controls every room. |
| Administrator sets a tablet scope; card sets `control_rooms` | Card wins, then the user scope, then stay rooms. |
