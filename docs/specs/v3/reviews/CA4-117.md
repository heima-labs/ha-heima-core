# CA4-117 — global overflow closure versus nonblocking admission

**Status:** specification reviewed (2026-10-17).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 0 §4.6: admission, cycles and HA commands never block on the retry
  queue; global overflow epoch, baseline invalidation, closure at a fresh intake's full append
  boundary; a crash before an opening is durable uses the unadvanced watermark. §4.4: the
  continuity watermark counts a discarded item as resolved only after its loss boundary is durable.
- **Evidence.** Implementation review `docs/v3/reviews/GLOBAL_CLOSURE_COMMIT_RACE_20261017.md`
  (implementation worktree): with the real queue and SQLite writer, a worker held inside the
  closing transaction committed the old closure while a concurrently admitted overflow advanced the
  in-memory loss; the durable open slot became NULL. A crash after that COMMIT and before the new
  loss's persistence would leave no trace of it in the epoch row.
- **Gap.** §4.6 required both nonblocking admission and that a further loss while the boundary is
  being established keeps the same epoch open; with one serialized writer both cannot hold.
- **Overlap check.** No new type. The new epoch is the existing global overflow epoch; the
  watermark invariant is §4.4's; the crash rule is the existing opening rule.
- **Owner.** Layer 0 §4.6, §13.

## Alternatives

1. **Boundary-position rule (approved).** The closure certifies only items at or before B; a later
   loss opens a new epoch. Nonblocking admission is preserved; crash safety comes from ordering and
   the existing watermark/interruption rules.
2. **Literal same-epoch rule (rejected).** Admission would wait for the closing COMMIT or a separate
   durable loss write. It blocks the hot path exactly when storage is slow or failing, contradicting
   §4.6's nonblocking rule and the single-writer design.

## Decisions (developer-approved)

1. A failed write or loss of an item at or before B before the closure is durable aborts it.
2. The closing transaction starts only after every item at or before B is durable or declared lost.
3. A loss after B before the closure is durable opens a new global epoch with its own boundaries,
   always global.
4. The new opening is persisted after the closure record and before any later retained item; the
   watermark cannot pass the loss meanwhile.
5. A crash between the closure COMMIT and the new opening uses the process-interruption rule.
6. Diagnostics count closures followed by an immediate new epoch.

## Scenario review

| Scenario | Result |
|---|---|
| Codex reproduction: loss at `(11, 1)` during the close of an epoch with B before it | Old epoch closes; new epoch opens at `(11, 1)` after the closure record. |
| Crash after closure COMMIT, before the new opening | Older epoch closed; interruption gap from the last durable watermark covers the loss. |
| Write of an item at or before B fails during closure | Closure aborted; gap stays open. |
| Cycle 12 facts retained after the loss | Written only after or with the new opening; watermark does not pass `(11, 1)` before it. |
| Admission during a slow COMMIT | Does not wait. |
