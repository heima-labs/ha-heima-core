# CA4-75 — committed-state observers

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision

Layer 0 §4.8: core components outside the DAG declare at bootstrap subscriptions to exact state
`FactIdentityKey`s and receive committed changes asynchronously after the cycle, coalesced to the
latest value, plus one initial value per process run. Layer 6 uses it for `quiet_hours.active`.

## Alternatives rejected

- Polling the latest-value index: arbitrary latency, periodic wake-ups, a second change-detection
  path per consumer.
- Layer-0 quiet-hours start/end events: a domain concept inside the generic runtime, a mirrored
  state transition (Layer 4 §3.1), and still no way to notify an out-of-DAG consumer.

## Overlap check

The latest-value index is read on demand; jobs and evaluation requests point toward the cycle.
Nothing notified a component after the commit, so §4.8 duplicates nothing. It writes no fact and
adds no semantic DAG edge.

## Scenario review

| Scenario | Result |
|---|---|
| Quiet hours end at 07:00 | Next committed cycle delivers `False`; Layer 6 releases held items. |
| Value flips three times before the subscriber runs | Only the latest is delivered. |
| Restart during quiet hours | Initial value after the first cycle keeps non-safety records held. |
| Subscriber raises | Diagnosed; cycle and other subscribers unaffected. |
| Plugin tries to subscribe after bootstrap | Rejected. |
| Value waiting in the retry queue during a storage outage | Already current state; delivered. |

Textual review only; no V3 runtime test has run.
