# CA4-104 — doorless passages and connections between floors

**Status:** specification reviewed (2026-10-15).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decision.** CA4-62: Topology records physical facts only; `door`/`door_window` are
  passable, `window` is not; `ResolvedConnection` per passable opening. CA4-103: map layout and
  opening placement.
- **Gap.** No construct for a doorless passage (archway, open plan, open staircase); a `door`
  stand-in admits contact Sensors and Actuators on a leaf that does not exist. Openings between
  floors were neither allowed nor forbidden; the map had no rule for them.
- **Overlap check.** `door` already covers every closable opening, on any floor. Nothing covered
  the doorless case. "Between floors" is derived from `floor_by_room`, so no new field is needed.
  V2's `access_type` (`stairs`/`elevator`) is not reintroduced: no V3 consumer distinguishes them.
- **Consumers checked.** Layer 3 exchange profiles and Layer 5 advice members and
  `safety.weather_protection` select openings only through `opening_faces_exterior`, which is
  always false for a passage. Layer 4 does not read connections. Layer 2 opening bindings now
  reject a passage. Presentation names compose from the type through translation keys, so they
  need no change.
- **Owner/dependents.** Layer 1 §7, §10 (owner); Layer 2 §3, §6 rules, §9 acceptance; Layer 8 §9;
  overview and recap orientation text.

## Decisions (developer-approved)

1. New passable `OpeningType` `passage`: no leaf, always open, interior rooms only, no orientation.
2. Closable means `door`, on any floor; between floors only `door` and `passage`.
3. A staircase is a connection or an ordinary one-floor Room with its own openings; no multi-floor
   rooms.
4. Map: passage drawn as a gap; floor badges; floors proposed bottom-up with vertical alignment.

## Scenario review

| Scenario | Result |
|---|---|
| Archway between kitchen and living room as `passage` | One `ResolvedConnection`; gap on the shared wall; no opening state; `opening_faces_exterior` false. |
| Contact Sensor bound to that passage | Rejected at staging. |
| Passage to `outside` or to a terrace | Rejected. |
| Passage with `orientation` | Rejected. |
| Door at the top of a staircase between floor 0 and floor 1 | Valid `door`; may carry a contact Sensor; badge on both floors. |
| Window with `other_side` a room on another floor | Rejected. |
| Staircase Room on floor 0 with a north window, a door to the entrance and a passage to the floor-1 landing | Window counts for exposure, sun and preferred side; landing proposed in the same cell when free. |
| Weather protection or ventilation advice on a house with passages | Passages never selected. |
