# CA4-103 — house map layout, orientation and device control

**Status:** specification reviewed (2026-10-15).
**Evidence type:** `textual_contract_and_scenario_review`, plus a non-normative interactive mockup
(real V2 topology, example orientations and devices) used by the developer to judge the visual result.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decision.** L8-C3a: native map in the Overview; automatic schematic "laid out by
  connections"; optional uploaded plan with `MapPlacement`; layout is Layer-8 presentation data,
  not `Topology`, saved as an immediate action; live overlays through committed-state observers.
- **Gap.** No layout rule (non-deterministic across implementations), no opening/device placement,
  no use of orientation, no rule for houses not aligned to north, no editing semantics (resize,
  concurrency, undo), undecided device control.
- **Prior art reviewed.** Smart-home products (SmartThings and Alexa Map View, HA community
  floor-plan cards) all start from a user-supplied or scanned plan, so none derives a map from a
  graph. Rectangular-dual floor-plan algorithms need triangulated planar adjacency graphs, which a
  door graph is not. Orientation as a boundary constraint and coarse grid encodings come from
  graph-to-plan research. No external dependency is adopted.
- **Overlap check.** `CompassOrientation` and `opening_faces_exterior` (Layer 1), `channel_kind` and
  the core solar Sensors (Layer 2), HA's more-info dialog and services are reused. `MapPlacement` is
  replaced by the narrower `MapRoomPlacement`, since openings and devices are derived. `exposure_by_room`
  is not reused because it omits doors and door-windows. No new Layer 0–5 contract.
- **Owner/dependents.** Layer 8 §3, §6.1, §9, §13, §15, §16; overview and recap orientation text.

## Decisions (developer-approved)

1. Automatic schematic only; uploaded plan removed from Initial V3.
2. Deterministic grid proposal with orientation as a preferred-side cost; frozen weights, fixtures.
3. Installation-wide up direction in 45° steps, suggested automatically; text upright.
4. Exterior rooms as strips outside the interior perimeter.
5. Orientation optional; a missing orientation is a map check ("approximate map").
6. Boxes resizable 1×1 to 4×3; drag and resize snap to whole cells; local undo per edit session.
7. Map device control through HA services and more-info as the signed-in user; security-relevant
   kinds never act on tap.
8. Residents: same map and control within HA permissions, plain language, no editor or checks.

## Scenario review

| Scenario | Result |
|---|---|
| V2 apartment topology, facades aligned | Hallway 3×1 hub; living/kitchen/study below, terrace strip below them; bedroom, small bathroom, entrance above. |
| Same house, all orientations +45° | Suggested `northeast`; same layout. Forcing `north` gives a different, less compact one. |
| New room added after edits | Pinned rooms unchanged; new room placed touching a connected room. |
| Admin drags the living room away from the hallway | Door drawn with connector; "Not adjacent" check; Topology unchanged. |
| Window side fully shared after a move | "Faces another room" check. |
| Resize onto another box | Refused. |
| Two admins save from the same revision | Second save rejected as stale; editor reloads. |
| Up direction changed | Warning, then floor placements cleared; undo restores them. |
| Room deleted from configuration | Placement ignored, dropped at next save; room and its entity disappear. |
| Tap on a light controlled by an active Reaction | HA toggle as the user; no `heima/v3/` message; divergence handled by Layer 0 §6; map shows the held automation. |
| Tap on a lock or garage-door cover | More-info only; no service call. |
| Resident with restricted HA permissions taps a light | HA rejects the service call; Heima adds nothing. |
| No solar Sensors staged | No sun overlay; `sun.sun` not read. |
| `prefers-reduced-motion` | Static rendering. |

Textual review only. The mockup is illustration, not evidence of runtime behavior. No V3 runtime
test has run.
