# CA4-66 — trial mode versus resident advice

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decisions (approved, B1.1–B1.4)

`notification_only` is the trial mode only. Resident advice is an explicit per-member delivery
(`advice`), limited to descriptor `advisory_intents`, delivered after administrative authorization,
once per activation and member, through a typed `ReactionAdvisoryOccurrence` and the Layer-6
`reaction.advisory` event fact.

## Overlap check

Not `reaction.follow_up` (a skipped/unconfirmed decided action), not `automation.availability`
(a blocked automation), not the administrator preview (diagnostic). Reuses the unified outbox,
`OperationalEventValue`, activation lifecycle and the existing member/staging/guard path.

## Scenario review

| Scenario | Result |
|---|---|
| New Reaction in trial | No command, no resident notice; admin preview only. |
| Authorized exchange advice on a manual window | One advisory per activation; no `ApplyStep`. |
| Same condition re-evaluated every cycle | Still one advisory (operation id per activation/member). |
| Advice member plus command member, consent missing | Advice delivered; command waits for consent. |
| Advice member without Actuator on an interior opening | Rejected at staging. |
| Advice for an intent outside `advisory_intents` | Rejected at staging. |

Textual review only; no V3 runtime test has run.
