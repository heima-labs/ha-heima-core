# CA4-92 — closed opening vocabularies; `Opening.entity_id` removed

**Status:** specification reviewed (2026-10-14).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decision (approved, S7 of the CA6 reread)

- Layer 1 §7 owns `OpeningType = door | window | door_window` (`door` and `door_window`
  passable) and `CompassOrientation` (eight compass points). Layer 2's solar mapping references
  it instead of restating the list.
- `orientation` stays optional; consumers that need it (the solar formula) require it.
- `Opening.entity_id` is removed; opening state comes from a `Sensor` with `related_opening_id` or
  an `Actuator` channel with `opening_id`.
- No new opening type in Initial V3; a garage door or gate is a `door`; a horizontal skylight
  needs its own geometry review.

## Alternatives rejected

- Keeping `entity_id` as a presentation or discovery hint: a second, uncontracted path to opening
  state.
- Validating only in consumers: late errors and the same list restated in several places.

## Overlap check

The orientation vocabulary already existed in the Layer-2 solar mapping; it moves to its owner.
The removal follows the CA4-84 `access_type` precedent. No new construct.

## Scenario review

| Scenario | Result |
|---|---|
| Opening with `type="Porta"` or `orientation="N"` | Rejected at staging. |
| Interior window toward a garage without orientation | Valid. |
| Solar formula on an opening without orientation | Rejected at formula staging (unchanged). |
| Serialized topology with `entity_id` on an opening | Rejected as an unknown field. |
| Window contact sensor bound with `related_opening_id` | Supplies the opening's state to the map and Reactions. |
| `door_window` to the terrace | Passable: one `ResolvedConnection`. |

Textual review only; no V3 runtime test has run.
