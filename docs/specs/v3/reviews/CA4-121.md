## Decisions (developer-approved 2026-10-19)

1. `household.guest_stay` `{"active", "guest_room_ids"}` and `household.planned_absence`
   `{"active", "start", "end", "end_beyond_horizon"}`, produced once by the core in Layer 2.
2. Sources: calendar category (one classifier per fact) and panel declarations by residents and
   administrators; union; no HA `switch`.
3. Calendar-declared stays use administrator-configured default guest rooms.
4. A panel declaration starts at its save instant; the end is optional for a stay, required for an
   absence; declarations survive restart.
5. Calendar failure: a stay stays active if a panel declaration is active, otherwise unavailable; an
   absence becomes unavailable.
6. Planned absence reads a 14-day horizon to coalesce adjacent windows.
7. `CalendarPlanBinding` is removed; descriptors read `household.planned_absence`.
8. Declaration actions on the Overview for residents and administrators; configuration in People.

## Scenario review

| Scenario | Result |
|---|---|
| Calendar event "Ospiti" | `guest_stay` active with the default guest rooms. |
| Resident declares "Guests, room 2" without end | Active until ended. |
| Guest account or tablet calls `household/declare` | Rejected before Layer 2. |
| Absence 1–7 and 7–10 from two calendars | One active interval 1–10. |
| Panel absence while the calendar read fails | `planned_absence` unavailable; programs undecidable, no false exit. |
| Panel stay while the calendar read fails | `guest_stay` active. |
| Three-week holiday | Active, `end_beyond_horizon=true` until the end enters 14 days. |
| One event "on holiday, grandparents at home" | Both facts active. |
| Restart with an active declaration | Declaration kept. |
| Absence declared from the panel vs the calendar | Same `AbsenceProgramState`. |
| Resident ends a panel absence early | `normal_cancellation` of the current activation. |
