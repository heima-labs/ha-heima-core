# CA4-26 — presence-simulation session versus HA schedule authority

**Status:** specification reviewed (2026-10-10).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Approved decisions and exact gap

Layer 0 §3.1 assigned every administrator-authored recurrence to HA's `schedule.*` helper, while
Layer 5 §7.2 configures the presence-simulation session as `WeeklyRecurrence` plus `Window` in
Heima. Overlapping occurrences, timezone edits and midnight crossing were also undefined. The
developer confirmed the product flow: the calendar records only the absence; lights, density and
the time window are configured in the presence-simulation Reaction, which is an ordinary
Reaction activated by the calendar absence and stabilized `away`. Reading the window from a
`schedule.*` helper (which needs a new instant interpretation for `next_event`) and from a
recurring calendar event were considered and rejected for usability. The developer also chose
the hybrid learning direction: Initial V3 stays unlearned (PS-1 confirmed) and the future
`TemporalActuationProfileModel` is the intended successor, always bounded by the configured
window and lights.

## Reuse and owners

Layer 0 §3.1 now limits the HA-schedule rule to standalone schedules and defines a descriptor
time-window parameter. Layer 5 §7.2 owns the session rules, reusing `WeeklyRecurrence`, `Window`,
the existing DST policy, the next-step slot and the `wall_clock` job basis of CA4-20. Layer 3 §8
records the hybrid direction. No new type, scheduler or HA helper is introduced.

## Scenario review

| Scenario | Required result |
|---|---|
| Every day 22:00, 3 h | Ends 01:00 next day; belongs to its start day. |
| Every day, 24 h | Staging rejects overlap. |
| Spring-forward 02:30 start | Starts 03:00, lasts full duration. |
| HA timezone edited during a session | Current session keeps its end; next start uses the new zone. |
| Clock discontinuity during a session | Session-end job re-armed as `wall_clock`. |
| Session window active but no calendar absence or not `away` | No activation. |
| Standalone admin routine such as quiet hours | Still uses a `schedule.*` helper. |

This is document-level evidence; no V3 runtime test has run.
