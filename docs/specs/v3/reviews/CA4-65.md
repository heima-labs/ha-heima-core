# CA4-65 — unified notification outbox and response ingress

**Status:** specification reviewed (2026-10-12).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Decisions (approved)

D1: one Layer-0 notification delivery outbox for every notification to a person, generalized from
the former follow-up-only outbox. D2: one authenticated response ingress with registered owners.

## Overlap check

The outbox reuses the former §4.5 transaction and operation-id rules and Layer 1
`PersistedProjection`; it is distinct from the §4.6 retry queue and the Recovery checkpoint.
The ingress reuses the existing `resident_response`/`admin_command` boundary checks of §5.1 and
the governance-ledger rule for actor references; it replaces the implicit, recovery-only ingress
of §7.4.1. No Layer-1 contract changes.

## Scenario review

| Scenario | Result |
|---|---|
| Availability notice rendered | Event fact and `ready` record commit together. |
| Crash after destination accepted, before `delivered` | Message may repeat; `notification_key` lets the destination suppress it. |
| Follow-up boundary | `prepared` intent first, as before; then `ready` with the fact. |
| Outbox storage down | Notification best effort with a diagnostic; cycles and commands continue. |
| Resident approves a recovery confirmation | `VerifiedResponse` reaches `layer0.recovery_confirmation`; compare-and-swap of §7.4.1 decides. |
| Response with a guessed or expired request id | Rejected at ingress; owner not called. |
| Admin answers a resident-only request | Rejected at ingress. |

Textual review only; no V3 runtime test has run.
