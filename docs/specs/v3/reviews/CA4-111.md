# CA4-111 — phones and accessibility

**Status:** specification reviewed (2026-10-16).
**Evidence type:** `textual_contract_and_scenario_review`.
**Runtime test:** `not_run_v3_not_implemented`.

## Impact record

- **Existing decisions.** Layer 8 §13: Lit custom panel on HA's frontend base; §5.1 addresses;
  §9 map (reduced motion already required for overlays); §12 languages.
- **Gap.** No phone, touch, history, keyboard, screen-reader, contrast or scaling requirement; no
  non-graphic map.
- **Overlap check.** Reuses HA components, themes and breakpoints, §5.1 addresses and §9.8
  controls. No contract toward other layers.
- **Owner.** Layer 8 §5.3, §9.11, §9.12, §16.

## Decisions (developer-approved)

1. 360-pixel minimum, HA breakpoints, card lists, one-column forms, fixed pending-changes bar.
2. 44×44 touch targets; every function by touch.
3. Back gesture through addresses.
4. WCAG 2.2 AA target, verified by automated and keyboard tests.
5. Logical CSS properties for future RTL locales.
6. Map list view with the same states and controls, no editor.

## Scenario review

| Scenario | Result |
|---|---|
| Resident answers a consent request on a phone | Works at 360 px, by touch; back returns to the notification's previous view. |
| Keyboard-only administrator applies a change set | Every step reachable with visible focus. |
| Screen reader on the Overview during frequent updates | Grouped polite announcements, no interruption per cycle. |
| Occupancy for a color-blind viewer | Text or pattern beside the color. |
| Text at 200% | No loss of content or function. |
| Map via screen reader | List view with the same states; lock opens more-info. |

Textual review only; no V3 runtime test has run.
